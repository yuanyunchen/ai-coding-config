## 任务说明



### 目标
把现有 Agent Harness 配置系统迁到当前目录，以 workspace-management v4 管理，并提供实际文件和历史的查看入口。

### 背景
用户认为已有工作区，希望挪到当前目录，之后系统性升级。现有 ai-coding-config 是 Git 配置仓，尚无 v4 工作区标记；旧的 harness 整改和工作区升级任务另在归档目录。

### 要求
- [x] R1：实际仓库迁入当前目录，保留完整 Git 历史与迁移前未提交文件。
- [x] R2：用 ws 创建工作区、任务、目标、计划、进度、结果和索引。
- [x] R3：能直接查看配置文件、历史提交、需求原文和对话记录。
- [x] R4：保留旧路径与全局记忆相邻路径的兼容性，管理命令可用。
- [x] R5：登记升级基线与待办，让后续系统性升级从本工作区继续。
来源：用户原文 p20261116。

### 约束
不把迁移前改动混入本轮修改；不运行真实 pull/deploy/sync；保留归档任务原貌；对话记录留本机，不提交个人会话；本轮不重构全局 harness。

### 验收标准
- 迁移前版本化及未忽略文件逐项 SHA-256/软链核对；仅 README.md 与 CLAUDE.md 有本轮预期修改。
- 原 HEAD 和全部既有提交仍在；原有未提交变更逐项保留。
- ws check 无 error；任务可按标准门槛收尾；用户原文已归档，inbox 清空。
- 新旧入口 help 与 memory status 均成功；deploy --dry-run 使用新工作区路径。
- README 可导航到配置、历史、任务和升级入口；逐一检查目标存在。

### 输入
原配置仓：迁移前路径与基线见 input/migration-before.json；用户原文见下方原文记录。

### 未定事项
无。系统性升级的具体范围留待 T02 基线审计后形成方案。
