# 计划 — T02 Harness 基线审计与系统升级

## 方法
先确认实际加载行为和单一配置来源，再处理确认的问题，最后按平台验证。节点保持 planned，后续开工时依实测调整范围。

## 阶段
| 阶段 | 范围 | 指标与判定 | 执行 |
|---|---|---|---|
| 运行基线 | Claude、Cursor、Codex、Trae 的规则、skills、commands、agents、hooks、settings 和插件入口 | 全量列出适用入口、来源、加载证据与差异，无静默截断 | 只读文件清单、CLI/平台检查与源仓对比 |
| 问题台账 | 规则冲突、重复入口、路径、三系统边界、日志与同步 | 每项标注证据、影响和是否复现；待验证单列 | 从任务原文和实物核对，不凭记忆补规则 |
| 方案排序 | 台账中所有确认问题 | 优先修复导致行为错误、记录丢失或升级回滚失效的问题，其次整理冗余 | 每项记录改动点、验收、回滚和授权边界 |
| 分批升级 | 已有授权或获批的变更 | 对应行为测试/探针通过，相关引用一致，旧有规则未意外改变 | 走 harness-management；仅在所需范围同步 |
| 收口 | 配置、任务记录、项目定位与版本 | 必要检查通过、结果可读、历史连续 | 工作区 update 与相应版本登记 |

- 源仓与运行目录是否一致尚未全量对比，不以本次迁移代替基线审计。
