# 忙时 Slack 首答实测

已部署的桌面首答路径让原 Codex 回合同时保留插话和回帖确认。对能直接回答的短问，完整的公开正文有一次性起止标记。桥接只检查准确回合中的已完成 commentary，并按当前讨论、来源、票据和撤回状态重新授权。未匹配的桌面输出不发送。实际工作仍在原会话运行。

| 忙时样本 | Slack 发问 → 答复回执 | Chrome 点击 → 首次观察到正文 | 首段完成 → 桥接记录送达 | 送达后多久才收到确认命令 |
|---|---:|---:|---:|---:|
| [中文 @](https://app.slack.com/archives/C0CJN63KC66/p1795000881735129) | 31.798 秒 | 32.129 秒 | 0.213 秒 | 1.631 秒 |
| [英文原帖追问](https://app.slack.com/archives/C0CJN63KC66/p1795000921624439) | 24.181 秒 | ≤35.774 秒 | 0.337 秒 | 23.651 秒 |

两个样本在 Slack 同一根帖分别产生一条可见答复，均无内部标记。英文浏览器观测存在采样间隔，不能用上界当作精确可见时刻。上次两条类似问答的 Slack 往返为 52.443 秒和 31.090 秒，两轮负载、采样时间和输入不完全相同。本轮证明交付早于回帖命令；样本不支持总体 p95 达标或精确的整体提速判断。

从桌面接受到首段正文被桥接取得仍有约 30.9 秒和 23.8 秒。此时段含桌面调度、落盘与模型处理。首答观察器只在已确认的目标回合以 500 毫秒间隔读取，时间窗口为 90 秒；其余情况继续走原有回帖命令。
