# Slack 持久记忆与收发账本

## 结论
- 已在独立代码仓实现可运行的 Store，使用 node:sqlite、WAL 和事务。受众绑定使用 team/channel/thread + project/backend，仅已授权目的地的事件进入上下文；解绑后也禁止把同一 agent 会话重新绑定到其他受众。
- 话题索引随来源更新，工作区和项目摘要只取当前授权频道内可见资料。中英文决定、承诺、待办及已发送答复以引用和可查 Slack ts 输出。中文用 Intl.Segmenter 分词并入 SQLite FTS5；上下文预算显式传递，达到时返回省略提示，精确原文可按 ts 读取。
- 消息编辑修复摘要和检索索引；删除和文件撤权清理当前内容，重放旧事件不能还原已删除消息及撤权附件；支持按频道设置保留期水位。附件本地下载信息与可提供模型的引用字段分开。
- 持久化入站去重、执行状态及重启恢复，独立记录待发送、发送中、未确认、Slack 成功收件、进度修改和文件交付。正文承诺与执行成败由各自账本承载。
- 用户输入和原文证据保留原语言；面向用户的状态和模型回复由主任务的语言路由处理。

## 验证
- 在代码仓运行 node --test test/store.test.js：9 项通过。覆盖重启、原文回执、周五测试承诺与周一排期、部分发送、重复入站、编辑/删除、过期事件、附件撤权、频道隔离、禁止会话跨受众重绑定和 CJK 检索。
- Node 24.1.0 的 node:sqlite 提示实验性；FTS5 和 WAL 已在该机实测可用。

## 需要上层处理
- 管理员的保留期限尚未指定。expireBefore(teamId,channelId,cutoffSlackTs) 可由运营策略调用；接入工作区时明确保留期限与备份清理。库标识来源覆盖为“本机观察的事件”，无法恢复缺失历史。
- 当前摘要为按来源维护的提取式索引；决定候选、承诺类别是规则匹配，任何语言均保留源文。没有实现无监督的权限提升、语义裁决或承诺自动结项。团队内本身有争议的说法仍需代理结合作者、执行结果和新证据判断，不能承诺100%自动判断。
- 相同事件提交状态不明时保留未确认。上层应在有明确拒绝时才 markRetry；回流或可靠送达证明后调用 markSent。成功更新 Slack 状态消息时调用 markUpdated。
- 实际 Slack 经内部成员上传、修改、删除、断线恢复与真实收发延迟，需由主任务联调验收。本派发没有发送外部消息。

## 续派结果
SQLite 向后兼容地增加 inbox.messageId、后端会话消费游标、实际展示过的消息与附件引用。桥接能在模型 RPC 前登记 messageId，重启后以相同 ID 对账。contextPacket 返回实际写入上下文的来源时间戳与水位。撤回信息时按实际依赖找到 Codex 和 Claude 会话，事务中冻结绑定、禁止重新接入已污染会话并清理本地由这些会话产生的公开回复；跨线程引用也沿依赖链处理。保留原 Slack 上已公开的内容。

复验 node --test test/store.test.js：11 项通过。新场景验证重启后的 messageId、跨 provider 的来源精确隔离、撤回后级联清理本地派生内容。删除绑定时同时返回原绑定快照以供上层中断对应后端。完整双端 HTTP/Socket 实际发送由上层验收。
