## 需要上层处理

1. **发布前，恢复失败要关闭出入口。** src/codex.js 的 resumeThread 核查共享会话权限；src/bridge.js 的 recover 捕获错误后留着绑定，并在末尾调度待处理消息，handle/event 不依赖本连接已验证的名单。权限不符或恢复失败时，把该会话保持为待核对状态，并在接收、发送和事件投影三个入口阻止使用，恢复成功才解除。src/main.js 的启动/重连顺序也需防止验证前的窗口。依据为审查时 bridge.js:219、230、232 和 main.js:33。
2. **网络送达不确定时需要可观察的恢复状态。** bridge.js 的 send 在发出前将 outbox 设为 sending。超时且没有收到 Slack 自身回流时，下次恢复不能证明已投递；应保留 unknown，暴露操作员核对入口，并确保正文、附件、执行完成分别记账。对 Slack 明确拒绝的情况记录失败；重新执行 coding 任务不应成为重发答案的前提。对图片渲染失败已增加纯文本图稿兜底。
3. **发布验收**：真实已绑定频道、两个内部参与者、进度与 20 个样本的 ACK 延迟尚无本次审查证据。Slack 成员检查、频道检查和消息发送是不同的网络请求。线上 p95 应在实际成员触发后测量；Socket Mode 已连接或本地毫秒测试不等于达成该指标。Claude 用户界面真实双向测试、配额或权限问题须分开陈述，remote stop 的能力边界在 CLAUDE-MEDIA.md 有说明。
4. **离线缺口**：当前存储摘要注明 observed events only。未见启动时回查 Slack 离线期间遗漏的消息及删除的流程；对团队成员公开必要的覆盖提示，并根据撤权及保留策略重新校验源材料。缺少授权数据时冻结不安全的上下文输出。
5. **默认受众**：管理员配对前确认当前频道对内部成员、访客的可见性。slack.js 限制发令者必须是活跃内部成员；即使发令者合格，群内其他读者仍能看到机器人公开回复，内部非 Slack Connect 频道也可能容纳单频道访客。建议使用内部专属频道承载共享项目输出。
