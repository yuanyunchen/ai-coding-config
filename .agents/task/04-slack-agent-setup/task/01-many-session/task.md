## 任务说明










### 目标
让 Slack 的 test 讨论接入正在使用的 Codex 窗口，后来的接管申请剔除同一讨论旧绑定。
### 背景
Mac 桌面进程直接持有当前会话；另一 app-server 直接 resume 会遇到 writer 冲突。桌面可发现自己的会话并转交输入。
### 要求
- [x] 核对桌面 owner 和实际会话，活跃时直接 steer，空闲时处理同一会话。
- [x] 新申请立即撤销旧绑定收发；未就绪期间持久保留待投递消息，仅最新绑定接收。
- [x] 保留相邻讨论的独立路由，校验异步发送时绑定仍有效。
- [x] 对 Slack 消息类型、路由、权限和交付进行系统验收；所有者带图追问保留原会话。
- [x] 公开回帖使用简短自然语言，架构题按需生成 PNG 并核实原线程回执；去除本机技能署名。

- [x] 交付下一阶段升级计划，含职责、互动、主动通知、媒体、正确性与速度门槛、独立验证和分工。

- [x] 实施稳定性与回复质量升级，使用独立故障注入、真实 Slack 浏览器、模型盲评、同机六组 A/B 验收，输出发布报告。
- [ ] 获得多人、Claude、真实接管的附加环境并验证忙时回复延迟达标。

### 约束
频道成员的项目权限保持隔离；只有经 Slack 认证的所有者文字直接进入桌面会话。桌面应用保持打开。
### 验收标准
真实桌面当前回合接收验证文本；真实 Slack 帖子收到从当前会话发出的回帖；旧绑定移除；全量回归通过。
### 输入
现有 Slack 桥接与已授权 test 频道。
### 未定事项
桌面应用内部接口在未来版本更新后需复核。
