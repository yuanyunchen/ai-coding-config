3Inside each paradigm

What is each paradigm, and what made it better or worse? The comparison above shows each paradigm at its best; this part opens them one by one, in the same order.

3.1

Embedding + trained head

Sees each page's screenshot as an image embedding, the request, and the page's code and HTML structure; a small head is trained on past votes to score each page. No language-model call: under USD 0.25 per model.

3.1 · how a trained head works

How a trained head works

Frozen encoders describe each page; a small head trained on votes turns that into a score.

How it works

Only the head is trained, on votes before each launch month; the encoders are used as they are.

Data past pairwise votes of known models (training); the new model's pages on the same tasks (scoring). Model image embedding + text encoder + HTML counts, frozen; a linear head or small network trained on votes.

3.2

Multimodal LLM, fine-tuned — the main system

Sees the page's screenshot through a multimodal language model (Qwen-VL); its weights are adapted to past votes and a linear head on top scores each page. Each adapter costs USD 8–14 to train once; scoring a new model needs no API call.

3.3

LLM, prompted

A language model (GPT-6 Luna) reads the request and both pages' screenshots and says which page wins; nothing is trained — only the prompt and the calibration of its probabilities change. About USD 0.18 per model in API calls.

3.3 · how a prompted judge works

How a prompted judge works

A language model states a preference; calibration and predicted votes turn it into a placement.

How it works

Nothing is trained. The prompt is improved by the loop below; the calibration is fitted once.

How the prompt is improved: a loop over its own errors

Steps 1–5: votes of known models; step 6: models the loop never saw.

Data no training votes for the judge; known models' ratings for the calibration; for the loop, votes of known models only. Model GPT-6 Luna with a fixed prompt, optionally a folder of rules from its errors.

3.5

Mixture of experts

Averages the ratings of several raters above: two members added on the development set, the fine-tuned member fixed after the test set was opened; it sees what its members see and costs the sum of their costs.

3.5 · how the mixture works

How the mixture works

Three raters place the new model; their ratings are averaged with equal weights.

How it works

Two members were added on the development launches, one at a time while the error fell; the fine-tuned member was fixed after the test set was opened.

Data the members' ratings of the new model; members chosen on development launches. Model equal-weight mean of the fine-tuned model and two trained heads.

4Why not closer: bias, noise, capacity, data

4.2 · noise, capacity or data?

Noise, capacity or data?

Held-out accuracy peaks while training fit is only 60–63%: much of the gap is vote noise.

Held-out votes10,901 votes from the last weeks, models known and new

How to read Each panel tests one explanation of why accuracy stops near 59%; the dark line is accuracy on votes the head never saw.

NoiseIt starts memorising the training votes after 2 passes, when it fits only 63% of them.
CapacityA model 700 times larger memorises more but predicts no better.
DataThe last doubling of the votes added 0.3 points [−0.3, +1.0].
On votes a rematch confirmed, the rater scores 58.0% against an ideal of 65–86%: noise alone does not explain the whole gap. The fine-tuned model shows the same picture: held-out accuracy peaks at the end of the first pass (57.7%), then falls to 55.3% while the training fit rises to 64.6%; the four-times-larger adapter fits training votes faster (68.3%) and is no better (55.2% held-out, 57.2% never-seen).
