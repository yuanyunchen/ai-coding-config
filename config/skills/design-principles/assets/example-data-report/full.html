1Task and measures

What is placed, and how is it scored? Before any number: what the rater does, the three measures and the one comparison every card uses.

1.1 · how to read the numbers

How to read the numbers

One comparison for almost every card: the newly launched models against the online board.

Definitionsused on every card that follows
Past votespairwise votes and pages of the models already on the board
→
Raterjudges the new model's pages against incumbents' pages on the same tasks
→
Boardits predicted votes place the new model; no real vote of it is used
→
Online boardDesign Arena's public board: the reference, never an input
Every card, unless its tag says otherwise: the 17 newly launched test models, every task of each model, against the online board of 2026-11-19.
  • Test set: 41 models the rater never saw. 25 of them are on the online board, in 30 placements: the 17 newly launched models and 13 held-out placements: models from families never used to choose a configuration (10 scored for the clean check in 2.1, 3 not finished). Cards on the prompted judge use all 30 placements.
  • Other sets, named on the tag: the development set (other never-seen models, used for every choice) and held-out votes from the last weeks of the data.
Pairshare of real votes predicted correctly; a coin gets 50%
Elo differencemean absolute gap between the predicted and the online rating
Rank differencemean absolute gap in rank among the 66–84 models on the board
  • Tournament: one task on which several models' pages are voted on; a model gains real votes tournament by tournament.
  • Predicted votes: the rater's verdicts, used like votes to place the new model.
  • Our real data (dark dashed line, the limit): the board fitted from all our real votes, compared with the online board for the same models — the distance between the two boards, not a bound.
  • Intervals: 95%, models resampled by family (a maker's line of models).

Data all votes from 2026-01-01 to 2026-09-29; test set as defined above. Model as named on each card.

What is each paradigm, and what made it better or worse? The comparison above shows each paradigm at its best; this part opens them one by one, in the same order.

3.1

Embedding + trained head

Sees each page's screenshot as an image embedding, the request, and the page's code and HTML structure; a small head is trained on past votes to score each page. No language-model call: under USD 0.25 per model.

3.1 · how a trained head works

How a trained head works

Frozen encoders describe each page; a small head trained on votes turns that into a score.

How it works

Only the head is trained, on votes before each launch month; the encoders are used as they are.

Data past pairwise votes of known models (training); the new model's pages on the same tasks (scoring). Model image embedding + text encoder + HTML counts, frozen; a linear head or small network trained on votes.

3.3

LLM, prompted

A language model (GPT-6 Luna) reads the request and both pages' screenshots and says which page wins; nothing is trained — only the prompt and the calibration of its probabilities change. About USD 0.18 per model in API calls.

3.3 · how a prompted judge works

How a prompted judge works

A language model states a preference; calibration and predicted votes turn it into a placement.

How it works

Nothing is trained. The prompt is improved by the loop below; the calibration is fitted once.

How the prompt is improved: a loop over its own errors

Steps 1–5: votes of known models; step 6: models the loop never saw.
