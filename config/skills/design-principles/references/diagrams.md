# 作图

关系图、流程图、架构图、hero 图怎么选型、怎么画。统计图见 `data-honesty.md`。出处见 `provenance.md` G 系列。

---

## 一、先判是否该画图

撰写或审查每一段时判断它是否该用图。满足任一特征就画:

| 内容特征 | 信号词 | 图型 |
|---|---|---|
| 多步骤操作或决策路径 | 先…然后…最后、步骤 1/2/3、如果…则…否则 | 流程图 / 泳道图 |
| 系统或模块间依赖与交互 | 调用、依赖、上游/下游、请求→响应 | 架构图 |
| 上下级或从属 | 汇报给、隶属、团队结构 | 组织 / 树 |
| 时间线或阶段演进 | Q1/Q2、里程碑、阶段一→阶段二、日期序列 | 时间线 / 里程碑 |
| 因果或归因 | 根因、原因、导致、影响因素 | 鱼骨图 / 归因条 |
| 多方案多维度对比 | vs、方案 A/B、优劣 | **表**(维度多时)/ 对比图 |
| 层级递进或优先级 | 基础→进阶、L1/L2/L3、核心→外围 | 金字塔 |
| 数值趋势 | 时间序列、增长/下降、百分比变化 | 折线 / 柱状 |
| 漏斗或转化 | 转化率、从…到…留存 | 漏斗 |
| 发散或归纳结构 | 维度、分支、多层嵌套列表 | 思维导图 |
| 循环或飞轮 | 正循环、闭环、A 驱动 B 驱动 C | 飞轮 |
| 占比分布 | 占比、份额、加总约 100% | 饼 / 树状图 |

不画图的情况:同字段横向对比(用表)、只有两三步的线性短流(一句话或 ASCII 即可)、去掉所有连线后仍成立的「关系图」(那其实是列表或表)。

## 二、选型分层

| 场景 | 首选 |
|---|---|
| 框架、概念关系、全景、总结 | 关系图(SVG / graphviz) |
| 公式化多阶段链路、逐步推导、同名变量在不同阶段取值不同 | 等宽 ASCII 图 |
| 同字段对比、参数、现象-决策对照 | 表 |
| 方案对比、Before vs After | 两栏分栏 |
| 多条并行主线的状态、归因、机制对照、多人分工 | hero 图(第六节四原型) |
| 关系本身是重点、需要可探索的关系网 | 交给 frontend-pipeline 的 starmap 分支(另做探索器) |

关系图与 ASCII **分层不互斥**:高层鸟瞰交给关系图,逐阶段公式细节交给 ASCII。不用 ASCII 当全景,也不把全部图都做成同一种形式。

## 三、节点与边

- **节点三层**:粗体标题(可含术语)→ 分隔 → 做什么 + 关键公式/参数。节点文字 = 标题 + 简短说明,说明 ≤ 12 字为佳,不写长段落。
- **形状 = 语义**:圆角 = 数据对象/信号/变量;方角 = 模块/计算(见 visual-encoding §三)。
- **边必标**:每条边写清传递的具体数据或公式(`rank_bid = cpa_bid × coef`、`uid + ad`),不画无标签箭头。例外:纯「下一步」顺序的流程(泳道步骤、操作序列)可在图例里写「箭头 = 下一步」代替逐条标注;携带数据或公式的边仍须标。
- **无凭空变量**:每个输入都有入边,由有身份的外部对象提供(用户、上游系统、模型预测、调控模块);外部对象画出来并标明身份,不写「外部输入」。因变量由输入 + 公式/模块推出,不跳步。
- **闭环**:回路、反哺用虚线回指并标一句话,不让读者自己拼。
- 不同阶段拆成独立节点;图中用真实对象名,禁用 A/B/C、表1/表2 等代号。

## 四、布局与连线

- 尽量水平或垂直布局,用直线或正交折线(水平→垂直→水平);连线不穿卡片、不交叉成网;标签贴近对应边,压线时挪到线的另一侧或垫底色。
- **线性顺序流左右排**,不排成瘦高竖条;节点 ≥ 7 的长链折成多行(每行 4–5 个),填满矩形区。
- **比例**:宽高比目标 1.3–1.8(16:9 到 4:3);横向阶段带可放宽到 ≤ 3;拒绝高 > 宽 × 1.2 的竖条。≤ 6 节点的小图 ~1.2 即可交付。
- **信息量匹配需求**:「简单架构图」3 层每层 2–3 节点;普通 3–4 层每层 3–4 节点;「完整」才到 4–5 层。流程图 6–10 步 + 1–2 个分支。每组 2–5 个节点,超过 5 个拆子组;一行超过 5 个拆两排。
- **连线数量策略**:≤ 8 条逐条画;9–15 条取代表性连线;> 15 条改层到层或精简分组。有连线的节点间距 ≥ 40。
- 手绘 SVG 没有自动布局:同排顺序 = 写坐标的顺序,按读者期望顺序给 x。
- 嵌套子图的方向设置在 mermaid 中不可靠;需要严格折行时用 graphviz `dot`(`rankdir=TB` + 每行 `rank=same` + 隐形排序边)。

## 五、分层展示

- **全景图**:只画高阶段过程与谁连谁,细节藏进大节点;不堆公式、不展开变量。
- **分图 / 模块图**:展开某一阶段的内部细节。主图比分图更简;主图已经塞进参数、时序、收益数字和全部字段,说明层级失败,拆图。
- **收口图**(长文结尾):比开篇全景**更全**——纳入正文讲过的数量、机制、旁支与回路;不是开篇图的复制,也不引入正文没讲过的新概念。
- 主图和分图不重复相同细节;不为「多作图」机械增加没有新信息的图。
- **每张图后有一段自然语言解释**(通常 3–5 句),不只有图,也不逐句复述图中文字。

## 六、hero 图(信息密度高、自动布局排不出的图)

四种原型,动笔前挑最像的复制骨架(模板在 `../assets/diagrams/`):

| 要画的 | 原型 | 模板 |
|---|---|---|
| 多条并行主线的状态全景(上游 → 现状 → 要交的) | 三列泳道全景 | `hero_lane_panorama.svg` |
| 一个数字或现象的归因分解(基线 vs 现状 vs 修正后 + 量级) | 双轨对照 + 量级条 | `hero_attribution_bars.svg` |
| 一个机制为什么坏了、怎么改 | 前后对照条 | `hero_mechanism_bars.svg` |
| 多人待办的分工与节奏(谁 / 何时 / 谁卡谁) | owner 泳道 + 时间列 | `hero_owner_timeline.svg` |
| 体系总览入口(主链带 + 平行路线 + 远期侧栏) | 开篇全景 | `panorama_overview.svg` |
| 长文结尾收口 / 每篇开头的全链定位 | 收口图 / 定位图(位图参照) | `closing_summary_b1.png` / `locator_b2.png` |

**统一版式**:

```
┌ 标题 ─────────────────────────────── 图例(右上:色块 + 一句语义)
│ 副标题 ← 一句话结论,不是「本图展示…」
├──────────────────────────────── 分隔线
│ 列/段小标(疏排、浅灰、加粗)
│ 主体:卡片 rx≈10、约 1.4px 描边、语义填色;正交走线,标签贴段
├ 横切/共同项:整宽虚线灰带(与主体实色块区分)
└ 页脚 ← 来源 + 哪些数是示意/待确认
```

- 边距左右约 48;卡片横向间距 ≥ 90(放边标签),纵向 ≥ 24。
- owner 编码:卡片左侧 4px 色条 + 右上姓名胶囊;同一人全图同色,图例点明。
- 卡片正文 3–4 行以内;完整 SQL、长条件不进节点。
- 每张图 ≤ 3 个字号层级、3–4 个主色组。
- 字体栈:`'PingFang SC','Hiragino Sans GB',sans-serif`(中文),不靠默认回退。
- 模板中的事实内容是范例,换内容不换骨架。

## 七、导出位图(需要 PNG 时)

内联 SVG 优先(文字可选中、可缩放)。需要位图(嵌入文档、PDF)时用 headless Chrome 截图,2–2.5 倍渲染:把 SVG 包进 HTML,`--screenshot --window-size=W,H --force-device-scale-factor=2.5`。Chrome 不在 PATH 时用完整路径。截完**自己打开 PNG 看一遍**(见 verification.md 渲染自查)。
