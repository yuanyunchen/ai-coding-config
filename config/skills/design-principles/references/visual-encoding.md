# 视觉编码

颜色、形状、字号、图例与克制度怎么表达信息。只管承载信息的元素;版面审美归 frontend-pipeline。出处见 `provenance.md` V 系列。

---

## 一、语义配色(同色同义)

**规则**:先数清产物里有几类语义,每类一种颜色;同一语义全产物同色,同一颜色只表示一种语义;图例必须写出语义,不只写颜色名。颜色编码含义,不编码顺序。

**默认语义色板(亮色)**:

| 语义 | fill | stroke | 文字 |
|---|---|---|---|
| 上游 / 输入 / 数据源 / owner A | `#EAEEF7` | `#4A5E8C` | `#2C3A5C` |
| 主线 / 处理 / owner B | `#E4F1F7` | `#2C7A9B` | `#14495E` |
| 焦点 / 受限 / 待定 | `#FDF1DE` | `#C8811F` | `#6E4408`(强调 `#B5462F`) |
| 负向 / 风险 / 失败 | `#FBEAE6` | `#B5462F` | `#7A2A18` |
| 产出 / 目标 / 达成 | `#E7F1E8` | `#3F7A4E` | `#234A2C` |
| 横切 / 团队 / 中性 | `#F1F0EC` | `#8B8F86`(虚线) | `#4E5249` |

底色 `#FBFAF8`(暖白),中性描边 `#C7CFD3`,连线 `#8C99A0`,次要文字 `#75838B`,分隔线 `#E6E2DB`。

**深色模式**:语义不变,只换明度——fill 用该色相的深底(约 15–20% 明度),stroke 提亮一档,文字用浅色。手绘 SVG 图若不做深色适配,放在浅色卡片里显示(卡片在深色页面中保持浅底),不要让浅底图直接贴深色背景。

**受限 / 待定一律走琥珀**:图里出现琥珀,就必须在图注、页脚或卡内说清「待谁确认」。

**分阶段链路配色**(成套图跨篇一致):上游/入口 = 靛蓝,召回/候选 = 天蓝,打分/精排 = 琥珀,评估/横切/调控 = 石板灰,收益/产出 = 绿。焦点节点用琥珀描边高亮,不被分区色覆盖。

**分组配色**:每组一种颜色(全图 2–4 种);分组容器浅色填充,组内节点白底 + 该组深色描边;同组节点视觉完全一致;连线统一灰色,不抢节点。

## 二、颜色不独立表意

- 红绿表示正负或涨跌时,**同时**带 ↑↓ 或 +/-(色觉无障碍)。
- 状态色配文字或图标;只靠颜色区分的状态视为缺陷。
- 避免红+绿作为唯一区分;橙+绿、红+棕同理。避免浅底上用黄系(对比不足)。相邻系列不用相近色相。

## 三、形状与线型

- **形状 = 语义**:圆角/胶囊 = 数据对象、信号、变量;方角 = 模块、算子、计算。过程节点与数据对象必须有不同形状或底色,不能让读者误判对象数量。
- **线型 = 关系**:实线 = 主数据流;虚线 = 回灌、复用、弱依赖、比较。图例说明线型。
- 卡片圆角约 10,子块约 6,小标签约 4;描边约 1.4px。
- **数量用长度表达**:量级条、覆盖率条比写数字更快被读懂;示意比例须在图注声明「非实测占比」。

## 四、字号与层级

- 同一图或同一组件 ≤ **3 个字号层级**;同级元素字号完全相同;相邻层级差 ≥ 4px(逻辑值)。
- **按实际显示像素判断**:图被缩放显示时,显示字号 = 逻辑字号 × (显示宽度 / 画布宽度)。正文、边标签、图例、页脚显示后 **≥ 11px**;放不下就删字、拆图或加画布高度,**不许缩字**。
  - 例:1160 宽的画布显示在 700px 列里,缩放 0.6,逻辑正文需 ≥ 18 才显示 11px;若画布按 1:1 显示,逻辑 ≥ 12 即可。
- 手绘图参考层级(1:1 显示时):图标题 20–27,卡片标题 13.5–15,卡片正文/边标签/图例 ≥ 12,页脚 ≥ 11.5。
- 页面正文 15–16px,行高 1.55–1.65;等宽数字用于对齐的表格列。
- 标题用独立文本,不塞进形状标题栏;短标签居中,长文本左对齐。

## 五、克制

- **元素响度匹配重要性**:主操作在场但不喊叫(比满饱和低 10–15%,阴影更柔);次要控件(已选 chip、复选、分段切换)用柔和/半透明强调,不用满饱和色块。
- 一个强调色,用得少;一屏内不堆多个高亮块;删掉只为「显得重点」而无新信息的高亮。
- 装饰不喧宾夺主;同一屏不堆砌视觉元素;保留相当比例的无高亮基础内容。
- **无关元素判据**:每个视觉元素(图标、徽章、标签片、色块、连线、分隔线)都要答得出「删掉它,读者少知道什么」,答不出就删。实测反例(2026-11 dashboard):每位候选人卡上都显示同样的「Stable 100% / 2/2 decisions」;几十个节点的关系图默认连线又粗又亮,盖住节点;只为显得重要加的警示徽章。
- 微调按幅度表达(「按钮再暗约 10%」),保留既有风格,不在要求微调时整体重做。
- 克制度校准参照:`../assets/demo-recall-metrics.html`(按钮权重、单一强调色的用量、文字详略)。

## 六、控件默认值

- **自由文本输入**:默认值不预填,显示为幽灵占位(同字体同字号、调暗);用户留空则提交时回落默认值。
- **分段按钮 / 切换 / chip(固定选项)**:默认项加载时即选中,`aria-pressed="true"`;单选语义下点已选项不取消。
- **多选 chip**:默认全选,允许逐个取消,提供「全选 / 全不选」;操作按钮文案反映实时数量。

## 七、Emoji

不设禁令。按克制原则使用:不替代图标语义、不在同一屏堆砌、不进 SVG 图(SVG/PNG 中 emoji 渲染不稳定,用图形代替)。

## 八、实体卡片与总览页

> 2026-11-04 沉淀(dashboard 返工:名字与标签顺序改了两次、卡上出现加权分、要点被截断、详情抽屉太密)。

- **卡片层级固定**:名字(最大字号)→ 特征标签(体现这个对象的特色,不限定词表)→ 要点(一条一行,完整显示)→ 关键数据。标签已表达的特征不在数据区再写一遍。
- **要点不截断**:放不下就改写短,不用省略号截断;截掉的半句话比没有更糟。
- **卡面数字 = 可直接核对的原始事实**(PR 数、revert 次数与比例、评审过的人数),每个配一句它说明什么;加权分、综合分、中心度之类只进详情,并附公式。读者看不出怎么算的数字不上卡面。
- **总览页下半部分不做平级折叠列表**:改成卡片网格,每张 = 图标 + 标题 + 1–2 个关键数字 + 一句话,点开看细节。
- **详情抽屉按「结论 → 证据 → 明细」分段**,每段一个主题,明细默认折叠。
- **定出结论的那一步要在页面上**:展示方法或流程时,最终做决定的环节(谁定的、凭什么)不能缺;只展示输入阶段,等于没回答「为什么是这几个」。
