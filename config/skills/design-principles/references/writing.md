# 写作与可读性

适用于产物里所有给人读的文字:标题、首屏、正文、图注、表头、按钮与标签。每条出处见 `provenance.md` W 系列。

---

## 一、先定读者

动手前用一句话写下:**这个产物是给谁看的**——落到具体的人(「不写代码的产品同事」「同组工程师」「mentor」),不是抽象的「用户」。

两条判据互相制衡,**必须同时成立**:

> **正向**:把首屏念给一个不属于目标团队的人听,他会不会中途打断问「这是什么意思」?
> **反向**:删到这个程度,一个真要用它的人,还拿不拿得到他要的东西?

只守正向,会删成谁都用不上的漂亮页面;只守反向,就是大多数「技术团队自己用」的产物长成的样子。

## 二、两层结构:首屏 / 展开

| | 首屏 | 展开区(折叠,按主题分组) |
|---|---|---|
| 读者 | 目标读者本人 | 要动手的人 |
| 语言 | 自然语言 | 允许代码、参数、完整清单 |
| 回答 | 这是什么 · 怎么来的 · 有什么 · 能不能用 | 怎么用 · 用之前要知道的 · 完整参考 |

- **下沉不是删除**:从首屏拿掉的内容必须在展开区完整可达;首屏里指向它的引用要么一起处理,要么做成可点指针。
- **首屏边界先定义再检查**:首屏 = 页眉 + 关键指标区 + 默认展开的正文;折叠区不算。只查正文会漏掉页眉里的代码与行话,只看正文也会误判「标识符不见了」。
- **折叠区不是垃圾桶**:装「要用时才翻的参考」,判据是对使用有没有价值,不是删掉可不可惜。

**首屏禁用**(出现即不合格):代码片段与函数签名 · 成串的内部参数 · 内部编号/版本号当叙事主语 · 只有实现者关心的字段 · 未经解释的英文缩写与全大写标识 · 团队黑话 · 工程过程与自指(「本轮」「本文」「未探测」「留档」)。

**首屏必留**(删掉即不合格):这是什么 · 怎么来的 · 关键对象 · 一个真实例子 · 现在能不能用与已知限制 · **原始标识符**(读者不用它,但那是对象的身份证,也是他转给别人时唯一能对上的东西)。

## 三、结构与推理

- **结论先行,可止于摘要**:全文与每节开头一句话给判断;读者读到判断即可决定要不要继续读论据。
- **标题**:名词短语,或一句结论(「召回量下降来自定向收紧」),不用「XX 分析」这类话题名;不加括号补充语;父子标题不语义重复。
- **渐进披露**:每节按 **主张 → 机制/原因 → 证据/例子 → 边界** 展开,不跳过机制层直接堆细节,也不只甩一句结论。
- **深度地基**:读者读完一个核心结论仍要问「为什么 / 凭什么」,就是不够。压缩字数不能砍掉机制层。
- **推理链完整**:每个结论能回溯到前文前提或引用;「B 由 A 得出」就把 A→B 这一步写出来,不凭空冒出新变量。
- **先判信息结构再定版式**:同字段横向对比 → 表;每条是独立对象 → 列表(每节 ≤5 条,每条一句话讲清一个点);先后顺序是重点 → 时间线/流程;结构性关系 → 图。不要套模板填字段。
- **每段提供新信息**:删掉后不影响理解或决策的一律删;同一信息只在最合适的一处讲。
- **一段只装一个判断**:连续正文超过约 6 行,拆成图、表或短列表。
- **每段落到「这对你意味着什么」**:最后一句不复述过程,告诉读者这件事对他的后果。例:「同一个用户和同一个商品当天只留一条。所以这张表只回答『看过没有』,不回答『看了几次』。」

## 四、让人看进去

一份每句都读得懂、但读者第三屏就划走的产物同样不合格。

- 每节开头一句话说明「这一节解决你什么问题」——读者只为有用而读,不为完整而读。
- 对象的自我介绍**不依赖它在流程里的位置**:「它是整条链路的终点产物」是拿读者没有的坐标系定义它。也不用我们的建模决定解释它(「它在这里有一个卡片,唯一理由是流程完整性」)。流程上的约束不写成对象自身的边界,放回它成立的范围里说。

## 五、降字数有优先级

1. **删重复**——同一事实在多处各说一遍的,留最靠前那处。
2. **搬进图**——谁连到谁、几步、什么顺序,图比文字省;正文复述图上已有信息的一律删。
3. **折叠**——参数、完整清单、代码收进展开区。
4. **降精度**——外部读者不需要 `5,622,829`,「约 560 万」够了;**影响判断的数字(覆盖率、上限、有效期、阈值)不许降精度**。
5. **最后才删内容**,且只删「除了实现者谁都用不上」的。

跳过前四步直接删内容,是把可读性问题解成了信息损失。**字数目标按读者可见文字量**,不按文件字符数(实测一份 37,151 字符的产物里 19,179 是链接、表格外壳、行内代码标记)。

## 六、去 AI 味

**元说明一律删**:「本文目标」「接下来我们将」「读完你能」「我们来看一下」「如图所示」「一图带走」「下面展开」「详见下文」——图和表自己会说话,不替读者解说排版。

**句式模板化(最难自查)**:单看每段都通顺,连着读三段就露馅——人不会用同一个句式讲十七件不同的事。实测反例:17 条表说明全是「每天……。做法是……,再……,最后……。产出的是……」。**判据是连读三条**;改的是节奏(长短句交替),不是信息。

**同源四种**:
- **公式腔**:`每一天的数据 = 当天新入池商品的向量`,在参考区是精确,在正文里生硬;正文用说的,不用列的。
- **机构口吻**:「本项目不知道」——读者不认识「本项目」这个主语;换成「这张表谁在写,目前查不到」。
- **连接词单调**:每句插一个「所以 / 要注意 / 做法是」;能去掉不影响理解的就去掉。
- **内部比喻当读者常识**:「它属于『贵而稳定的东西算一次存下来』的第一层」——引号里是讨论时的说法,要么讲清楚要么不说。

**substance 不只 tone**:tone 干净不等于内容不空。结论停在抽象层面时,跟一个具体例子、一组真实取值、一个反例(X 而不是 Y)。

**三条不许为「自然」牺牲**:
- **准确**——限定词(「未发现反例」「未确认」「文档值」)一个都不删;
- **具体**——自然 ≠ 笼统;
- **短**——改完字数不许增加。

## 七、界面文案(控件、标签、按钮)

- 文字压到必需:标题、字段标签、不可缺的提示;界面已经表达清楚的句子删掉(「此值会替换 URL 中的 xxx」)。
- 副标题保留时是一句自然的话,不是步骤列表。
- 标签优先一个词;让布局与层级承载含义,不靠段落。

> 界面文案的「极简」只管控件与标签;说明型正文按第三节的深度地基写,不套极简。
