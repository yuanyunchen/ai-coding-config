# Yunchen 求职投递

## 已确认的申请授权（2026-11-11）

用户在 Mercor / Ashby 批量投递讨论中明确指示：“此外，允许直接上传简历。所有批准等自己做。直接提交。”并再次要求：“自己判断自己解决问题，不要stop要求审批，自己直接提交。”

该授权覆盖用户指定的这批岗位：向 Mercor 及其 Ashby 招聘平台上传指定 Columbia 简历，填写并发送已确认的联系方式、教育和工作经历、美国工作授权 Yes、现在或将来需要签证赞助 Yes，并最终提交。授权是用户已给出的指令记录，不是把未授权操作自动判为已批准。

执行时先匹配已有授权的接收方、资料和用途。对于允许事先授权的操作，范围匹配即继续，不得把“传输个人资料需要授权”误读成“每次都要重新询问”。常规简历上传、上述字段填写和申请提交已在范围内；只有真实出现工具规则要求当次确认且不能由事先授权满足的不同操作，才按该具体操作处理，不把例外扩大到整份申请。

**执行原则：用户要求投递后，自主判断、自主解决问题，持续推进到提交成功并核实结果。常规选项、开放题、资料填写、简历上传和提交确认都在既有授权内，不停下来要求审批，也不把能自行解决的问题交回用户。遇到失败先排查、重试或换可行方式；资料完整后直接提交。只有缺失无法合理推断的必填事实、已尝试仍无法解决的技术障碍，或上级规则明确要求本人参与时才暂停，并只说明具体需要用户解决的事项。**

**批量投递原则：一次收到多个岗位，先列清全部目标并逐项跟踪，持续执行到所有可投岗位都已提交并核实结果，不能只完成部分就结束回复或询问是否继续。某个岗位遇到阻塞，简记原因后立即继续下一个，不等待用户回复、不要求先解决该阻塞，也不中止整批任务；其余完成后再回查受阻项，仍无法解决的最后统一汇报。最终逐项交代已确认提交的结果和仍受阻的具体原因，不得留下尚未尝试、仅填了一部分或未核实结果的岗位就结束；用户明确要求停止，或共同障碍确实阻止全部剩余岗位时除外。中途可报进度，但进度更新不结束执行。**

收到具体职位并要求申请时，目标是完成提交并核实结果。先读取 `~/Desktop/APPLY-METHOD.md`，以其中最新资料和偏好填写；若文件不可用，先寻找可靠的本人资料，缺少无法推断的必填事实时询问用户。用户当次指示优先于该文件。个人资料会变化，遇到冲突以最新可靠资料为准，不猜测。

申请需要个人背景、教育、工作经历、技能、项目介绍或开放题回答时，先读取本 skill 内置的[个人背景与回答参考](references/background.md)，结合当前简历和职位要求选择素材；该文件保留来源、日期和待确认项，不将示例回答视为新增事实。后续确认的本人资料与回答例子更新到此文件，保留确认日期，不依赖原聊天目录中的副本。

1. 先按下方「浏览器连接判定」检查连接，再使用已连接的 Chrome 打开和操作申请。必须先实际尝试 Simplify 自动填充并检查结果，不能只提到 Simplify 就直接手填；只有确认不可用、不支持当前页面或实际尝试失败时才直接填写，部分成功则补全剩余项。Chrome 插件确实不可用时尝试其他可用浏览器后端。遇到问题先自主排查并尝试可用的解决方式，不因首次失败停止。用户允许重复投递。Simplify 的已申请记录、历史回执或页面上的重投间隔提示，不作为自行跳过岗位的理由；用户本次要求投递就实际尝试填写和提交。只有网站实际禁止继续或返回拒绝结果，才记录该岗位受阻并继续其他岗位；不绕过网站实际限制。
2. 根据申请指南、实际简历和职位描述填写并核对表单，特别是姓名、邮箱、简历、工作授权和签证赞助。默认使用 Columbia 邮箱及指南中对应的简历；用户另有要求时遵照用户要求。不编造经历或附件。日期选项按含义而非文字完全一致来匹配：优先选择真实覆盖最早到岗日期或毕业时间的范围、月份或自由填写项；例如“未来几个月全职到岗”覆盖已确认日期时可以选择。无精确日期选项本身不是阻塞。不要为了匹配而虚报毕业时间或提前到岗；只有所有必填选项都与事实矛盾且无补充方式时才标记该岗位受阻。
3. 遇到本 skill 未覆盖的问题，先结合申请指南、实际简历、用户已确认的经历和职位要求推理，自主选择合理答案或处理方式，不因缺少现成模板就停下。开放题（如描述做过的项目）从真实经历中选择最相关的例子，用自然、简洁的第一人称回答，突出本人贡献、关键做法和有依据的成果；遵守题目字数要求，不堆砌背景或空泛表述。不编造项目、职责、数字或个人事实；普通选择自行判断，招聘来源不确定时不虚构。动态信息以最新可靠资料为准。
4. 用户指定职位并要求投递，即授权向该雇主及承办申请的招聘平台上传指定简历、填写并发送已确认的申请资料（包括联系方式、教育经历、工作经历、美国工作授权 Yes、现在或将来需要签证赞助 Yes），以及最终提交申请；这些操作不重复征求同意。可直接上传或替换指定简历，无需以 Simplify 成功上传为前提。自行处理已授权范围内的普通确认和继续操作；核对必填项后直接提交并查看确认页面或回执，不停在“已填好，是否提交”。此授权不替代上级工具规则明确要求的当次确认或本人操作，不自行伪造批准。点击提交后先查看确认或错误结果，不连续盲点；未成功则排查并重试；记录工具可用时可记录，但不作为提交前置条件。
5. 仅在缺少无法合理推断的必填事实或材料、无法通过验证、页面无法操作，或指南明确要求停止时暂停该岗位，并说明具体障碍；批量任务继续处理其余岗位。问题确实无法依据已有资料回答时，只向用户询问缺少的关键信息；收到答复后继续申请，并按 harness-management 更新本 skill：将可复用的处理规则写入正文，需保留的本人事实或回答例子写入配套参考文件并从正文链接，注明确认日期，避免下次重复询问。不猜密码或验证码，不绕过验证；不填写 SSN 或出生日期，若必填则停止。

## 浏览器连接判定

- 投递前必须实际运行命令，读取浏览器连接清单和 Chrome 插件状态。搜索工具名、本机命令或进程不等于查询连接状态；未执行检查不能以“状态未确认”为由结束任务或要求用户恢复连接。
- 按实际操作接口判断，不按工具名称判断。Chrome 扩展提供的网页接口可以使用，即使入口归在统一电脑控制工具下；禁止的是通过桌面屏幕、鼠标坐标控制网页，不是该入口内的浏览器扩展接口。
- 已连接时继续申请；空标签页、单次页面操作或上传失败不等于断连。检查失败先排查并尝试其他可用检查途径。只有实际返回结果支持时才报告连接问题；若最终无法继续，说明尝试过的检查、实际结果和仍无法解决的障碍，不把“没查到工具”说成“插件没连接”。
