# 历史回填与首日 Bootstrap

## 1. 回填原则

- 复用正式单日 SQL，通过 Dorado 日期回溯逐日运行。
- 不写一个直接扫描完整历史窗口的超大 SQL。
- 从 3–4 并发开始，根据队列等待、单日扫描量和失败率调整。
- 单日失败只重跑对应日期；保留成功分区，不采样、不跳日、不重跑整个窗口。
- 提交成功不等于执行成功，必须追踪触发器与实例结果。

## 2. 输入完整性

上游完成应由 producer 实例、Sensor、ready 表或不可变水位证明。以下信号都不充分：

- 分区路径已经出现。
- 24 个小时标签各有至少一行。
- 行数短时间稳定。
- 固定延迟已经过去。

如果没有权威完成信号，只能明确标注近似等待策略，不能宣称完整。

## 3. 回填验收

回填完成需要四类证据：

1. Dorado：所有目标日期实例成功。
2. Metastore：所有物理分区连续存在。
3. 数据：分区非空，或符合明确的合法空分区合同。
4. 粒度：唯一键、合法键、金额/计数范围和源完整性通过。

数据日期集合与物理分区是两种证据。表扫描看不到零行分区，不能替代 metastore 回读。

源物理文件损坏时，只跳过已定位并获授权的损坏文件或时区，记录日期、文件范围和剔除量；不得扩大为全量静默忽略损坏。

## 4. Bootstrap 写前门禁

首日全量前必须确认：

- 所需历史分区全部成功并连续。
- Catalog/维表快照完整且版本排序确定。
- 参数合法，窗口与 TopK 数量满足合同。
- 目标表为空，或满足明确的首日覆盖重跑合同。
- 所有 join 输入已降到目标粒度。

写前检查必须独立于业务结果是否有行。空候选也要执行参数、输入和目标状态校验。

## 5. Bootstrap 写后门禁

至少验证：

- `COUNT(*) = COUNT(DISTINCT primary_key)`。
- TopK 边界、窗口边界和阈值边界。
- 排名唯一、连续、无空值。
- 来源集合数量与并集公式一致。
- 独立重算与正式结果双向 `EXCEPT` 为 0。
- 全字段分片指纹已保存。
- 同日重跑后集合、排名和指纹一致。

首日结果是后续状态任务的基线；门禁失败时停止日更接力。

## 6. 保留期与滚动语义

物理 TTL 应为业务保留期加数据延迟/清理缓冲。修改 TTL 时同时检查：

- 历史 anti join 是永久还是滚动窗口。
- 过期后是否允许重新 ADD。
- rank 是否仍能永久连续。
- UPDATE 应复用哪一条有效 ADD。

不能只改表 TTL 而保留相互矛盾的“永久注册”业务描述。
