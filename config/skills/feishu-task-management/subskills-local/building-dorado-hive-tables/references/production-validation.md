# 生产写入与质量验收

## 1. 写前与写后分离

写前门禁：

- 参数合法。
- 输入日期、分区、小时和上游完成信号完整。
- TopK/阈值集合达到合同。
- 历史状态唯一且一致。
- Catalog 最新版本排序无冲突。

写后门禁：

- 行数、唯一键和事件类型。
- 排名范围、来源拆分和边界。
- 独立双向差集。
- 分区指纹。
- 下游 SQL 返回 schema。

写后发现问题不能替代写前阻断。

## 2. 校验必须强制求值

校验表达式不能只挂在可能为空的业务结果上。成熟日零新增时，非法参数或历史损坏仍必须失败。

目标引擎要真实验证：

1. 零新增 + 非法参数。
2. 零新增 + 输入/TopK不足。
3. 历史唯一性或排名损坏。

每组都应任务失败，并证明原目标分区行数与指纹不变。

## 3. Overwrite 安全

不要仅依赖“Spark 通常原子提交”的经验。对正式写法执行受控失败测试：

- 写前保存目标分区行数和分片指纹。
- 制造可控断言失败。
- 确认任务失败。
- 重算行数和指纹，必须完全一致。

Spark 读取并覆盖同一 Hive 分区时，先写任务专用临时路径，验数后再覆盖正式分区。

## 4. SQL 引擎兼容

- SG ByteQuery/Calcite 可能无法规划“相关 `NOT EXISTS` + 聚合右表”。先把右表收敛到唯一键，再用 `LEFT JOIN ... WHERE right_key IS NULL`；用双向差集证明等价。
- 数字正则通过不代表 BIGINT 安全，还要处理 0、符号、溢出和宽松模式转 NULL。
- 模板日期应形成可识别的分区谓词；Explain 检查实际 PartitionFilters。
- 最终写入边界显式 CAST 到目标 schema，不依赖粗粒度 schema 推断。

## 5. 状态与序列语义

- 用户覆盖：日内唯一边，跨日再次按 `user_id × product_id` 精确去重；不能累加每日用户数。
- 用户序列：保留重复和真实时间顺序；不能用覆盖边恢复。
- 截断快照只服务快速读取，不能用于精确商品覆盖。
- 同时间事件只能承诺确定性排序，不能声称恢复源未记录的现实先后。

## 6. Dense / 派生字段回灌

- 保留原事件行，不因空文本删除事件。
- 候选 UPDATE 还要比较最终派生文本；文本未变化的候选应抑制。
- 本地与线上一致性可使用固定哈希稳定样本，覆盖所有类别、空值和边界，不必全量复算。
- 下游依赖派生任务成功，不能读取刚写入但尚未回灌的中间状态。

## 7. 最终验收清单

- 正式实例成功，分区存在。
- 主键唯一，非法键为 0。
- 窗口、TopK、阈值和排序边界正确。
- 双向 `EXCEPT` 为 0。
- 同日重跑幂等。
- 受控失败不覆盖。
- 参数、版本、依赖、资源和告警回读一致。
- 下游 SQL 真实运行，列名、顺序和排序符合合同。

任一硬门禁未通过时状态为 BLOCKED；不以抽样、旧数据、空分区或任务壳替代正式完成。

## 8. 检查器本身怎么写(2026-07-31 一轮实战的代价换来的)

> 本轮**新写**的检查器里,**有 3 个在变异测试中被自己抓出缺陷**。
> 结论不是「写得不够仔细」,而是:**检查器天然偏向「通过」** ——
> 它的失败路径最少被执行、最少被测试,而它一旦坏掉,
> **表现与「一切正常」完全一致**。所以下面每条都是写法约束,不是心态提醒。

### 8.1 每个新检查器**先做变异验证**,判据是「只有被伪造项失败」

伪造**被检查的对象**(不是伪造检查器),确认:
① 被伪造项**报失败**;② **同组其余项仍然通过**。
只满足①不够 —— 一炸全炸的检查器没有分辨力,等于没有定位能力。

### 8.2 判据可能**真空成立** —— 必须配阳性对照

反例:断言「新字段全为 NULL」用来证明「字段是新加的」。
但**所有字段都读不出来时该断言同样成立**,两种情况不可分辨。

⇒ 加**阳性对照**:同一行的邻近旧字段必须**非空**。
更强的形态:让对照按**恒等式**成立而不是「非零即可」——
「非零」会放过一个只是有噪声、并非真正响应伪造的对照。

### 8.3 判据**不适用**时必须判失败,不能真空通过

对「区间外、本就没有该类数据」的日期跑区间内的校验,阳性对照必然为 0。
此时检查器**必须报失败**并说明「对照没触发 ⇒ 上面那些零证明不了任何事」。

若判据写成「反例为 0 即通过」,这些日子会**全部误判为通过**,
并制造「多验了 N 天」的假象 —— **凭空多出来的信心比没有信心更危险**。

### 8.4 读不出来的那天,**正是最该看的那天**

检查器遇到「结果不可读 / 结果自报的身份不符 / 文件损坏」时,
**不得静默剔除该项**。实测过一个版本把读不出的天丢掉,
剩下 21 天全过就报 `exit 0` —— 而被丢掉的恰恰是最可疑的那天。

⇒ dropped 必须**计入失败**;`exit 3`(检查器自己没跑起来)**永远不得当成通过**。

### 8.5 闸门在「它保护的那次变更完成时」变红 —— 加**具名分档**,不放宽

钉死在「改前状态」的闸门,会在变更成功的**瞬间**恒红。
两种下场都坏:后续被堵死,或**操作者开始习惯性无视闸门** —— 后者更危险。

⇒ 改成多态:「改前」「改后」「上一代已部署版本」都是**有名字的合法态**,
且**报出当前是哪一态**;**第 N+1 种状态仍然报警**。
每加一态**必须变异验证**:伪造一个不在名单里的状态,确认仍然 BLOCKED。
—— 这是分档,不是放宽。

### 8.6 **先测再改门禁**,顺序反了等于拿假设改门禁

要把门禁的生效范围放宽/收紧(如把「从哪天起必须有该字段」前移),
**必须先实测该范围内确实满足新条件**,再改常量。

反过来做,改完第一次运行就会红,而**红因会被误读成业务问题**,
一个正确的修法被错误的表象否定。

### 8.7 分清「结构恒等式」与「真检验」

`SUM(CASE WHEN f THEN 1 ELSE 0 END) + SUM(CASE WHEN f THEN 0 ELSE 1 END) = COUNT(*)`
是**算术恒等式**,与数据无关,**验它等于没验**。

⇒ 写验收标准时逐条问:**这条判据存在能让它失败的数据吗?**
不存在 ⇒ 它不是判据,是装饰。真检验要落在**可能为假**的性质上
(如「该字段不得为 NULL」「与上游独立计算的口径交叉核对」)。

### 8.8 跨越多处的语义约定,**按概念穷举,不按语法搜索**

同一个常量可能有多种语法形态:`'20260724' AS x` 与 `trim('20260724') AS x`,
分处两条语句。按第一种写正则会**只改一处**,在同一文件内制造口径分裂。

⇒ 改这类约定时:先**穷举所有语法形态**,改完用**跨文件一致性检查器**复核,
并断言「旧值残留 = 0」。本轮正是靠这个检查器拦下了一次半截改动。
