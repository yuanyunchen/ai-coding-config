# 构建飞书机器人

把飞书应用、实时事件桥接、主智能体交互、定时推送与多组任务工作区组织成可长期维护的系统。先用 `feishu-task-management` 确认飞书执行规则；涉及工作区时同时使用 `workspace-management`。

## 场景路由

| 任务 | 必读 |
|---|---|
| 创建应用、配置权限、事件与本地常驻桥接 | `references/app-and-runtime.md` |
| 设计 Bot 名称、头像、reaction、回复节奏与语言风格 | `references/interaction-and-identity.md` |
| 管理多组日报、订阅、群上下文与主/子智能体分工 | `references/workspace-orchestration.md` |
| 测试 reaction、@ 回复、推送、防重、重启与头像 | `references/test-and-rollout.md` |

执行具体命令时再读取飞书入口下的 `lark-shared`、`lark-im` 与 `lark-event`；不要在本 skill 复制其完整命令手册。

## 核心原则

1. 运行时只管平台和安全：真实 @、授权、会话隔离、并发、超时、幂等与恢复。
2. 每条通过基础门禁的业务消息都交给 Codex；本地关键词、正则、快照和 resolver 只能提供事实，不能代替 Codex 回答。
3. 给 Codex 当前消息、同一用户的近期对话、候选工作区和可用能力，由它自主判断如何理解、查证、行动和表达。
4. 硬门禁只保护身份与敏感信息、应用级权限变更、重复发送、空结果和未经确认的高风险外部写入；用户在当前会话明确要求的任务配置变更（如当前群订阅、日报名称、关注项、中间指标、格式与调度）属于正常能力，不额外套静态白名单或人工批准。业务分类、回复方式和质量取舍不固化成规则。
5. 长期事实归对应任务工作区，跨任务方法才进入通用 skill；验收看真实结果、上下文承接和交互体验，不看模板命中率。

## 实施轮廓

1. 建立内部自建应用、最小权限、真实 @ 事件和固定 Bot 身份。
2. 事件桥接完成权威消息读取、安全门禁、持久 claim、reaction、pending 与一次 Codex 唤醒；具体可靠性细节见 `references/app-and-runtime.md`。
3. 把近期对话、工作区事实和领域能力作为上下文交给 Codex，不在桥接层解释业务。
4. 长期任务按子工作区独立保存与调度；群事件与定时生产分开，推送按订阅幂等执行。
5. 用真实群消息检查模糊问法、多轮纠正、并发、慢任务跟进和重启恢复。

## 边界

- 本 skill 只管机器人平台、运行与任务组织；查数、系统操作、报告生产等业务逻辑仍由各自领域 skill 管理。
- 不把 app secret、token、真实用户/群/业务对象 ID、具体关注清单或某个机器人的头像写入本 skill；这些属于对应工作区状态。
- 不用普通消息文本模拟真实 mention，不用 Incoming Webhook 替代双向群交互。
- 不把多个日报组塞进同一工作区后靠长对话猜上下文；上下文不清时只问一个简短问题。
- 不设置“无需 Codex 的业务快路径”；已验收快照、关键词命中和本地索引只能作为 Codex 上下文或工具输入。
