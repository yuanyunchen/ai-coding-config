# Bot 视觉与交互原则

这份参考只提供目标和边界，不提供业务意图分类器、固定话术或逐句脚本。真正的表达、工具选择、是否追问和回复节奏由 Codex 结合当前消息、近期对话与工作区事实自主判断。

## 视觉身份

- 名称让群成员一眼看懂服务范围；头像使用友好、清楚、缩小后仍可辨认的机器人形象。
- 具体名称、头像资产和发布状态保存在对应 Bot 工作区，不写入通用 skill。
- 头像更新后发布新应用版本，并在真实群聊回读；后台预览不等于线上已生效。

## 交互目标

- 像熟悉业务的同事：先回答眼前问题，简短、自然、清楚。
- 理解模糊表达和多轮追问；优先利用同一用户的近期上下文，不强迫用户提供系统 ID。
- 已有可靠事实时直接回答；需要现查时可先给有信息增量的简短反馈，再补结果。是否需要这一步由 Codex 判断。
- 只说明对用户有用的状态，不暴露进程、队列、重试、回执、文件路径或内部角色。
- 不重复承诺或结论。连续追问只补充新状态、新判断或新链接。
- 用户纠正优先；不借用群里其他人的上下文。
- 回复飞书 docx/wiki 时优先保留 Markdown 链接语义，让客户端生成原生文档预览；不要把标题和 URL 拆成普通文本。预览能否出现仍以真实群回读为准。

这些是体验目标，不是模板。不要把示例句、关键词或响应时序固化成运行时代码。

## Reaction

reaction 只表示“看到了”，不参与业务路由，也不替代正式回复。由 Codex或轻量呈现层结合整句语气，从已验证枚举中自然选择；同一事件只发一次，避免长期固定为某一个表情。

当前已验证枚举：`OK`、`DONE`、`OnIt`、`OneSecond`、`Typing`、`LGTM`、`THUMBSUP`、`THANKS`、`APPLAUSE`、`CLAP`、`FINGERHEART`、`SMILE`、`LAUGH`、`THINKING`、`SOB`、`CRY`、`FACEPALM`、`HEART`、`PARTY`、`CheckMark`、`CrossMark`。

- 枚举大小写敏感；新增枚举先用真实 Bot 身份完成创建、查询和删除 smoke。
- 明显相反的语境应避免，例如“未完成”不使用完成类 reaction。
- 除此之外不建立关键词到表情的一对一映射，让 Agent 保留风格和语境判断。

## 上下文与行动

- 运行时提供当前消息、同一发送人的近期对话、候选工作区和可用事实入口；Codex自行决定直接回答、读取事实、调用领域工具或追问。
- 任务事实和长期偏好写入对应工作区；跨 Bot 且已验证的方法才进入通用 skill。
- 应用权限、凭证、可用范围等高风险外部变更需明确授权；用户在当前会话明确要求的当前任务配置可由 Codex 自主执行。写入后回读确认，再自然说明结果；普通只读问答不因格式、辅助字段或复盘缺项被压住。

## 验收

用真实群消息检查结果，而不是检查是否命中某个模板：

- 模糊问题能得到相关回答，多轮纠正能承接上文；
- 简单已知问题及时回答，慢任务有自然跟进；
- 同一消息不重复回复，不串用户、不串工作区；
- 回复有可用结论和必要链接，不暴露内部实现；
- 头像、reaction 和语言风格自然且不过度重复。

默认采用精简验收：后端只覆盖即时进度、最终回复、去重/续接和文档预览这几条核心契约，再用一条真实群消息确认链路；除非本次改动触及权限、持久化或并发，不扩展成大规模场景回归。
