# 测试与发布验收

测试的目标是确认 Bot 对人有用、对话自然、系统可靠，而不是证明某套关键词、模板或分类器被命中。

## 验收分界

硬校验只覆盖平台和安全：

- 消息来自飞书真实群事件，且不是 Bot 自发消息；若订阅本身只投递群 @，权威详情中的 mention 缺失、ID 作用域错配或列表内混有不完整项不得成为静默拒绝理由；
- 不泄露凭证、隐私或内部敏感信息；
- 同一事件不重复 reaction、回复或执行外部动作；
- 空业务结果不冒充结论；所有尝试结束仍无结果时给一次简短可见状态，发送结果未知时不盲目重放；
- 修改权限、生产配置、线上实验或其他高风险外部状态前有明确授权。

业务理解、对象选择、是否追问、工具选择、回答深度、进度节奏和措辞不做本地硬门禁。运行时把当前消息、近期对话、工作区事实和候选证据交给 Codex；发现答案不理想时，保留原结果并改进上下文、工具、知识或 skill，不能增加一个本地规则回答来掩盖问题。

## 自动化测试

默认先跑与本次改动直接相关的少量后端契约，不为了形式完整重复整套场景。权限、账本、并发或恢复机制发生变化时，才扩展对应回归；链路已经跑通后，交互改动通常用聚焦测试加一条真实群 smoke 即可。

最小覆盖：

1. 真实群事件、Bot 自发消息、敏感内容和重复事件门禁；覆盖“事件已投递但权威详情缺少、错配或混有坏 mention 项”的回归，确认消息仍进入智能处理。
2. 权威消息读取失败后的持久恢复；长期账本不保存被拒绝正文。
3. 同一会话串行、不同会话有限并发、15 分钟上下文续接和服务重启恢复。
4. 每条通过门禁的业务消息都启动或续接 Codex；本地索引、resolver、快照和查询结果只作为上下文，不能直接回答，也不能覆盖 Codex final。
5. Codex 超时、非零退出、空 final、发送状态未知与重复投递不会产生重复消息；终态失败不能静默，可用但偏长的结果不能仅因旧展示阈值被整体丢弃。
6. 明确 flight 或权威来源身份冲突会阻断错误结果；region、日期、T/NT、模板等非身份差异只进入诊断和 Agent 判断，不在桥接层误杀整个回答。
7. 本地知识、只读查询和外部链接可被 Codex按需使用；队列繁忙只影响依赖它的调用，不冻结无关回答。
8. 定时推送与群聊事件分离，重复扫描或服务重启不重复推送。

测试失败是证据。用户改变目标行为时更新验收条件；实现缺陷则修链路，不改写失败结果或用更宽松断言伪造通过。

## 真实交互场景

发布前从实际使用中抽取一组自然请求，覆盖但不限于：

- 开放式能力询问和模糊对象；
- 已知事实的直接问答；
- 需要现查的单对象、多对象、分维度或历史问题；
- 多轮省略主语、纠正上一轮对象和连续追加条件；
- 两个用户或两个工作区并发；
- 任务配置、订阅或交付请求；
- 慢查询、工具不可用和部分结果可用。

场景只是覆盖面，不是固定话术。Agent 可以直接回答、先查、先给有信息增量的进度、追问一个关键问题，或在安全边界内执行动作；验收者根据语境判断它是否像一个可靠同事。

每轮从四个维度检查：

- 内容：对象、口径、范围和链接是否有用且没有明显误导；
- 上下文：是否承接同一用户的近期对话，是否接受纠正，是否串人或串工作区；
- 交互：是否回答眼前问题，表达自然，不重复，不暴露内部执行细节；
- 时延：已有事实是否及时，慢任务是否有合理反馈，最终结果是否在约定窗口内。

不要要求每条回复固定一至三句、固定先确认、固定发进度或固定使用某个 reaction；这些由 Codex按语境决定。

## 真实群验收

使用飞书客户端选择 Bot 形成真实蓝色 mention token，再发送全新消息。至少确认：

1. 原消息只有一次 reaction 和一次最终回复；如 Codex认为需要进度，也不能重复承诺或重复结论。
2. 后台存在唯一事件处理和唯一 Codex 启动/完成记录。
3. 模糊问题能得到相关回答，多轮纠正能承接上一轮，另一位用户不会继承该上下文。
4. 同一 event 重放、服务重启和 pending 恢复不会增加回复。
5. 无新事件时不唤醒 Codex；群聊请求不会顺带生产日报。
6. 结果中的链接可点击并落到正确对象；外部变更只有回读后才宣称完成。
7. 在处理中主动重启一次，等原 lease 到期后确认事件会被周期恢复且只完成一次；不能只验证“启动时恢复一次”。
8. 制造先到事件较慢、后到事件较快的并发，确认持久化到达顺序不被工作线程启动顺序覆盖，旧结果也不能压过新结果。
9. 对无法权威确认是否已发送的历史事件，验证其正文、lease 和重放入口均已清除；权限不足时记录“不确定但不重放”，不能猜测远端发送结果。

若无法安全获得第二测试用户，可用自动化隔离测试替代并明确记录未做的真实用例，不扩大线上白名单。

## 发布与回滚

- 安装后核对源码与安装态一致、旧 PID 已退出、新 PID 已启动、数据结构升级完成、服务 ready、pending/failed 状态和最新日志；只复制文件而未切换进程不算发布完成。
- 用安装态再做一轮真实 Codex smoke；仅单元测试通过不代表线上主链路已切换。
- 头像变更需发布应用版本并在真实群回读，小尺寸仍可辨认。
- rollout 记录应用版本、权限、事件类型、运行状态、真实验收、已知问题和可恢复方式；不记录凭证。
- 新版本若出现重复发送、越权或敏感信息风险立即回滚；普通内容偏差保留证据后继续迭代，不用本地规则接管答案。
