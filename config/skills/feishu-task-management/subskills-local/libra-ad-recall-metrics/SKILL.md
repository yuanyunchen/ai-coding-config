# Libra 广告召回实验指标

只读查看实验的主指标、召回中间指标、商品召回支路和转化事件，并给出能回溯到页面与时间窗的解释。

## 场景路由

执行前按任务读取：

| 查 ADVV、p 值、召回/商品支路、转化事件 | `references/metric-workflows.md` |
| 找页面、复用链接、减少重复点击 | `references/link-shortcuts.md` |
| 截主指标、中间指标或转化事件的精准卡片图 | `references/exact-screenshot.md` |

| 管理长期任务工作区、定时日报、主/子智能体分工与链接索引 | `references/daily-report-management.md` |

## 成功标准

1. 对齐 flight ID、实验名、region、实验状态、版本、`recall_type`/`queue_id`/`dpa_direct_id`、观察时区和时间窗。
2. 结束日是最后完整数据日；不能把组件名“数据产出助手”当成“数据产出中”。
3. ADVV 取自 `决策广告主价值Diff%`；p 值来自点击该单元格后的 `P-Value`。
4. 召回支路同时比较 pass count、支路独占消耗和支路总消耗；商品支路同时比较广告消耗和计费比。
4a. CID/召回中间指标的解释不能停留在“某事件有结果”或相对涨跌：按工作区定义的主路与支路逐项对账 pass count、总消耗、独占消耗、独占消耗率/计费比，先计算绝对增量，再判断消耗是主路保持、支路承接还是整体收缩。base=0 的相对涨幅只作为零基数提示，不作为有效增长结论；删除对决策没有帮助的空事件套话。日报正文只保留核心判断和不超过 3 组关键数据，通常 1–2 句；完整计算留在采集结果或 manifest。
5. 解释 CVR 与 ADVV 时按 `external_action_en` 拆转化量、广告主价值、消耗和计费比，不用总量猜事件结构。
6. 结论附可点击链接、绝对日期、时区、过滤条件和对照支路；推断明确标注。
7. 维护实验文档时按“信号 → 实验类型 → region → 日期”组织；类型统一写作 `广告召回`、`Combined 召回（CID + PID）`、`商品召回`，combined 不得归入纯商品召回。只有详情页状态为“进行中”的实验展开，历史日期折叠；每条记录包含精简核心参数以及实验详情、实验报告、中间指标、转化事件四个权威链接。
8. 截图必须是卡片级精准截图：只保留卡片标题、指标表头和对应结果行，不得带导航、筛选区、相邻卡片或显著性弹窗；浏览器原始截图必须再通过 `scripts/trim_metric_card.py` 的像素级横向收紧与硬验收，未通过不得交付；无有效指标时不截图。长期日报里，用户新增或开启中间指标默认包含每个指定支路各一张精准截图，只有用户明确说不需要截图时才可省略；缺图可以让其余内容以 partial 状态先交付，但必须列出缺失支路并继续补查，不能静默当作完成。
9. 日报沿用用户给定样板，按“实验类型 → 信号 → region”组织，不新增摘要卡片、加粗重点或其他自定义层级；概述只写主指标最后完整日和跨实验核心变化，不放中间指标日期。每个实验自己的中间指标折叠段必须写该数据源最后完整日，并在日期推进时同步刷新深度分析链接和截图，即使主指标日期未变。若有可用转化/事件拆分，紧跟中间指标建立独立默认折叠段，写自己的最后完整日、链接、判断和精准截图；没有有效结果表则只保留链接或明确无有效卡片，不伪造截图。随后再写关注实验数和最值得注意的 ADVV/p 值及简短判断，不逐条复述。默认只写主口径；展示值统一为 ADVV 两位小数、p 值整数，底层采集仍保留页面原始精度；正文不自行补写“置信/不置信”。
10. 日报实验集合以用户明确点名的 flight 为白名单；不得自行加入命名相似、调试中、暂无数据或只在旧文档中出现的实验。`nd` 从真实开始时间到最后完整数据日按数据产出计算，首个不完整产出日按 `0.5d`；实验关闭后的有效回流单独写 `+ md 回流`，不把自然日差直接当实验天数。
11. 长期日报任务中，主智能体负责理解、规划、派发、验收、文档交付、偏好与链接索引维护；所有 Libra 查数、实验发现、浏览器操作和截图由子智能体执行。子智能体只回传结构化结果、截图和权威 URL，不直接修改日报、关注清单或工作区记忆。
12. 日报信号与展示日期以任务 watchlist 为准：不能把实验列表筛选词、流量层或页面入口当成信号，也不能用实际流量生效日覆盖实验展示日期。中间指标折叠节必须紧跟对应实验，不集中堆到类型末尾。
13. 用户要求按可追踪状态拆分时，主报告筛选 `user_tracking_status`：`(0)可tracking` 为 T，`(1)不可tracking` 为 NT；分别查询、分别记录过滤条件和链接，不把 T、NT 或未筛选全量混为一个口径。
14. 只有用户明确要求回顾历史实验时才进入历史分支：按同信号组织候选，以页面证据筛除未起量的小流量实验，结束实验按真实产出核验 `<nd>d + 7d`，并把核验过的完整链接写回命中的任务工作区索引；不得据此扩张 ongoing 清单或日报 watchlist。
15. 长期任务启用 `skill-evolution=auto-authorized` 后，每次运行收尾都按 `references/self-evolution.md` 判桶：任务事实与偏好写工作区，可复用且已验证的方法自动最小修改本 skill、references、scripts 或 evals，并记录验证证据；无需再次申请批准，但不得扩张到其他 skill、权限、hook、全局规则或线上配置。
16. 若任务工作区明确声明该组主报告日期同步，日报先对工作区指定哨兵做最小日期检查。哨兵日期未推进且目标日期显示“数据产出中”时，记为 `data_pending`：停止主指标、p 值和主截图的完整采集，但不得记为 `no_data_update`，也不得据此结束当天任务；按工作区计划延迟复查。对 `show_intermediate=true` 的实验仍做轻量日期探针，分别记录其最后完整日和页面生成链接；若中间指标已推进，单独刷新链接索引并按工作区截图策略更新，不得继续复用旧 query。只有复查后确认主指标与所有启用的中间指标都没有新的完整数据，才发送“数据未更新”消息并复用上一期日报链接。未声明同步的任务不得自行套用这一短路。

## 快速流程

### 1. 建立实验卡

从实验详情页或实验记录文档记录：

- flight ID、实验名、region、状态、实际起止时间、流量；
- v0/base 与 v1 的含义；
- `recall_type`/`recall_flag`、目标 `queue_id` 或 `dpa_direct_id`；
- 实验详情、主报告及已有深度分析链接。

### 2. 冻结观察口径

从预计最新日期向前检查。目标指标区显示“数据产出中”就回退一天；第一个已有完整数值且不显示该状态的日期是结束日。所有页面使用同一结束日，除非数据源本身只产出到更早日期，此时单独标注。

### 3. 依次采集

1. 主报告：决策 ADVV、P-Value，必要时看累计差异值的天级曲线。
2. 广告召回中间指标：`Travel Recall` 模板，按 `queue_id` 比较目标支路与主路/其他支路。
3. 商品召回中间指标：`pid商品召回` 模板，按 `dpa_direct_id` 比较消耗与计费比。
4. 转化事件：`Travel Catalog Event` 模板，按 `external_action_en` 解释价值结构。

只执行用户任务需要的分支；不要为了“完整”打开无关页面。

### 4. 收敛结论

先回答：实验是否置信、支路是否起量、效率如何、价值来自哪些事件。再说明证据和仍未验证的假设。不要把正向 diff 自动写成置信，也不要把有 pass count 自动写成有业务作用。

## 核心口径

- `p < 20%`：按当前口径置信；`p >= 20%`：不置信。保留页面精度，不把阈值改写成 0.05。
- Non Custom Video 只在用户明确要求该细分口径时查看或写入；日报不得自行追加。
- `计费比 = 广告消耗 / 广告主价值(opt)`；越低表示单位价值所需消耗越少、效率越高。
- 广告主价值可按事件粗拆为 `Σ(事件转化量 × 单次事件价值)`。总 CVR 下降而 ADVV 上升，常见原因是高价值事件增加、低价值事件减少，或同一事件的单次价值提高。
- 只有实验组有数据而对照为 0 时，相对差通常没有解释力；比较实验组绝对值、主路和其他支路。

## 边界

- 默认只读；不点击 Stop、Pause、Start、Publish、Enable、复制实验或任何写入按钮。
- 用户明确要求维护实验文档时，只允许写指定飞书文档；Libra 页面仍保持只读。普通增量维护按 `feishu-task-management` 的文档写入流程局部更新；只有用户明确要求整篇重排时，才可在完整回读、保留资源和生成可核对 manifest 后覆盖，并立即回读验收。
- 不申请权限、不改实验、不改模板、不发布配置，除非用户另行明确授权。
- 页面 403/空白时先换允许的浏览器后端；仍失败则保留受阻链接。仅凭截图分析时必须标明“截图口径”，不能冒充实时数据。
- 指标出现异常但无法用本 skill 的三类页面解释时，转 `ad-recall-experiment-debugging`，不在本 skill 内扩张成全链路排查。

## 收尾检查

- 主指标、p 值、日期与过滤条件可复核。
- 支路比较没有混用 `queue_id` 与 `dpa_direct_id`。
- 计费比方向没有写反。
- 事件结论同时考虑数量、价值和消耗，不只看 CVR。
- 所有结论与链接属于同一 flight 和正确 region。
- 文档层级、combined 分类和折叠状态正确；每个 flight 恰有四类链接，链接显示文本与现有文档风格一致。
- 每张截图只含一个待解释的指标卡片；标题、表头、base/v0 与 v1 行完整，相邻卡片标题不可见。中间指标一支路一图，不同 branch 不得复用同一图片路径或使用拼接长图。
- 日报截图的有效表格应横向占满图片；右侧不得残留报表容器造成的大块空白。
- 截图与链接必须来自同一次页面回读，遵循 `page-generated URL + last_complete_date → branch capture → trim/visual QA → document update → remote re-read`；不允许只更新文字/链接而沿用旧图。中间指标和事件分析均一支路一图，不能把多个 queue/dpa/event 卡片拼成长图；右侧留白不超过 10px，交付前必须视觉检查。
- 浏览器工作结束后释放已接管的用户标签页。
