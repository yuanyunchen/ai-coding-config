# 长期召回实验日报管理

## 适用范围

用于已有任务工作区、关注 flight 白名单、用户样板和定时任务的长期日报。具体 flight、支路、时间和 URL 属于工作区状态，不写进本文件。

## 角色边界

### 主智能体

- 理解用户意图，维护关注清单、展示偏好、链接索引、日报规范和自动运行时间；
- 读取上一期交付，制定当天采集范围并创建派发留档；
- 回读子智能体结果，比较前后变化，验收 flight、region、日期、nd/md、指标精度、链接身份和截图边界；
- 写入飞书日报、设置折叠、回读验收并与用户交互；
- 仅查看本地截图或结构化结果做质量检查，不亲自操作 Libra 或浏览器。

### 子智能体

- 执行所有 Libra 查数、实验发现、页面导航、浏览器操作、p 值展开、趋势检查和精准截图；
- 先读工作区 MEMORY、watchlist、日报规范、链接索引、派发协议、本 skill 与任务所需 references；
- Libra 全程只读，不编辑飞书日报、工作区记忆、关注清单、自动任务或线上配置；
- 只把结构化结果、截图、异常和页面生成的完整 URL 写入派发目录。

主智能体不得为了省一次派发而直接接管浏览器；子智能体不得越过结果回传直接做管理或交付。

## 工作区最小真值

每日运行前必须能从工作区一跳读到：

1. `.agent/MEMORY.md`：任务入口、角色分工、外部文档与当前调度；
2. `.agent/memory/note/experiment-watchlist.md`：flight 白名单和中间指标开关；
3. `.agent/memory/note/daily-report-spec.md`：样板、层级、精度、折叠和截图规则；
4. `.agent/memory/note/experiment-link-registry.md`：可直接打开的权威 URL；
5. `.agent/agents/libra-daily-collector.md`：子智能体固定执行契约；
6. 上一期 `deliverables/YYYY-MM-DD/`：比较基线与交付 manifest。
7. `memory/note/skill-evolution.md`：本工作区是否授权自动迭代、待验证候选和最近一次成功迭代。

## 每日运行

### 1. 主智能体召回与派发

1. 完整读取最小真值和上一期交付。
   - 若命中工作区明确声明主报告日期同步，先创建最小 `date_probe` 派发，只检查工作区指定哨兵的最后完整数据日。
   - 哨兵日期与上一期相同、目标日期同时显示“数据产出中”：停止主指标、p 值和主截图的完整采集，不打开其他主报告 flight；但对 watchlist 中 `show_intermediate=true` 的实验仍执行轻量日期探针，分别记录其最后完整日和页面生成链接。若中间指标已推进，按工作区截图策略单独刷新；若未推进则不重复截图。保存轻量 `data_pending` 留档，按工作区计划延迟复查。该临时状态不得记为 `no_data_update`，也不得结束当天任务。
   - 延迟复查后日期推进：进入下列完整采集。复查后只有主指标与所有启用的中间指标都没有新的完整数据，才保存 `no_data_update` 留档，并向订阅群幂等发送一条“数据尚未更新”的消息及上一期日报链接。
   - 哨兵日期推进：再进入下列完整采集。工作区没有明确声明日期同步时，不得自行套用该短路，仍逐实验确认日期。
2. 按 watchlist 冻结当天 flight、主指标和中间指标范围；默认不展示中间指标。若任务启用转化事件拆分，事件分析作为独立折叠段紧跟中间指标段，不混入中间指标正文。
   - 信号与展示日期必须原样读取 watchlist。筛选词、流量层、页面入口和实际流量生效日都不是信号或展示日期的替代来源。
   - 对每个 `show_intermediate=true` 的实验展开指定支路，形成 `flight_id + branch` 级截图清单；用户新增或开启中间指标默认要求每个指定支路各一张精准截图，除非其明确要求只要文字或 link。
3. 为当天创建新的 `.agent/subagent/<module>/<date-or-instance>/task.md`，引用 workspace-management 的派发协议和上述文件路径。
4. 派出子智能体；所有浏览器操作留在该派发中。长任务由主智能体监督产物进度，但不代做。

### 2. 子智能体采集

1. 按链接索引直接打开详情、主报告和启用的深度分析页，不重新搜索。
2. 从预计最新日期向前确认最后完整数据日；不能把“数据产出助手”当成“数据产出中”。真实的“数据产出中”属于待复查状态，不是全天无更新结论。
3. 在页面日期控件更新窗口并执行查询；不得只改地址栏后直接读取旧表单。
4. 采集原始精度 ADVV、P-Value、nd/md 和精准截图；仅采集 watchlist 开启的中间指标。派发结果同时写出 `branch-screenshot-manifest.json`，逐 flight 记录 `metric_family`、`template`、`group_by`、required branch 与最终截图路径；每个 branch 另写 `observed_card_title` 和 `observed_columns`，不以图片总数代替支路对账。
5. 新链接必须由页面生成。把新 URL 作为 `link_updates` 回传；缺失时说明原因，不手工拼 query_id。
6. 关闭或释放本次接管的浏览器标签页。

主报告和中间指标可能来自不同数据源，最后完整数据日要分别确认。中间指标查询先在页面控件提交目标结束日，再回读页面新生成查询的结果日期；如果结果自动回落到更早日期，保留主报告的最新完整日，并在中间指标旁单独标注它自己的截止日。不能因为日报日期或主报告已更新，就把中间指标写成同一天。

### 3. 主智能体验收与交付

1. 验证每个结果属于正确 flight、region、模板和最后完整数据日。
2. 截图必须先通过 `scripts/trim_metric_card.py` 的像素级横向收紧与硬验收，再打开最终图检查纵向边界：主图只含 T&E Catalog；中间图只含一个目标支路；不得出现第二个 `queue_id`、`dpa_direct_id` 或事件卡片，也不得出现 Non Custom Video、筛选区、弹窗或大块留白。不同支路必须映射到不同的独立图片文件，禁止复用同一长图或后期纵向拼接。只保存了原始 DOM 截图或工具退出码非 0，均不得进入日报。随后运行 `scripts/validate_intermediate_coverage.py --manifest branch-screenshot-manifest.json`，同时验收 `flight_id + branch` 覆盖、路径唯一性和指标族身份：广告召回=`ad_recall/Travel Recall/queue_id/cid*req+独占消耗+总消耗`；商品或 Combined PID=`product_recall/pid商品召回/dpa_direct_id/广告消耗+计费比`。身份缺失、错模板、错分组、错字段或指定支路被全量汇总卡替代时均记为 `partial`，不能进入对应实验段。
3. 与上一期比较，只把新增变化和需要关注的内容写入标准蓝色概述。
4. 按日报规范创建或更新当天飞书文档；ADVV 两位小数、p 值整数，正文不补“置信/不置信”。替换既有图片时必须同时更新 token 与按最终图宽高比计算出的显示宽高，禁止复用旧图尺寸。
5. 中间指标使用独立普通折叠行并默认收起，直接紧跟对应实验；折叠行内第一行写该数据源最后完整日、页面生成 link，展开后依次是规范判断和一支路一图的精准截图。判断先给核心结论，再用不超过 3 组关键数据支撑，通常控制在 1–2 句；完整逐项计算只留在采集结果或 manifest。不得集中移到该类型所有信号之后。必要时先展示无中间指标的信号，保证“实验 + 中间指标”连续且折叠不吞掉后续信号。
6. 有效的转化事件/拆事件分析使用与中间指标同级的独立普通折叠行，默认收起，紧跟在中间指标折叠段下面；写自己的最后完整日、页面生成 link、简短判断和事件卡片精准截图。无有效结果表时不伪造图片。
6. 对新建日报执行 `subskills/lark-doc/scripts/set_document_l2.py <文档 URL>`，默认设为“ByteDance 内获得链接的人可查看”，且外部访问和邀请外部协作者保持关闭；只以 fresh readback `verified=true` 认定生效。用户明确指定其他权限时以其要求为准。
7. 回读文档并逐项验收链接、图片数、加粗范围、折叠状态、排版和公开权限；概述不放中间指标日期，日期只放各自折叠段。
   - 图片发布必须可安全重试：每次创建图片 block 前先回读目标父 block 的现有子块，以 `parent_block_id + 最终文件名` 对账；已存在的图片直接复用，只补缺失项。中断后不得靠列表切片、人工记忆“从第几组继续”再次批量创建。
   - 图片续传完成后，再按每个父 block 的期望文件名集合验收；存在重复文件名、空白图片 block、额外图片或缺图时，先清理或补齐，不能进入推送。
8. 支路覆盖结果为 `partial` 时，不阻断其余已验收内容先发布；但交付记录、群消息和重试队列必须明确缺少哪些支路，且不得把当轮标成完整验收。继续在当轮允许的查询窗口内补查，补齐后以新文档版本幂等更正。

### 4. 主智能体落盘

1. 用验收通过的 `link_updates` 更新链接索引；保留当前可直接打开的 URL 和最后验证日期。
2. 用户改变关注实验、支路或展示偏好时，先更新命中日报工作区的 watchlist 并回读确认，再回复变更已完成；写入或回读失败时可以先返回其他有用结果，但不能把该配置变更说成已生效。不回改历史派发日志。
3. 保存当天 manifest 与交付记录，更新 MEMORY 的当前状态和关键决策。
4. 自动任务时间或职责变化时，用应用的 automation 管理能力更新现有任务，不创建重复调度。
5. 飞书文档回读验收通过后，按父工作区启用的订阅行向目标群幂等推送一次；主动日报不挂人。推送成功后把群、消息 ID 和发送时间写回 manifest/delivery，失败则保留可重试状态，不能把“文档已生成”误记成“日报已完成”。
6. 最终只向用户展示日报链接、最新完整数据日、核心变化和需要其决定的事项。

### 5. 主智能体自进化收尾

1. 读取当轮用户反馈、子智能体结果、失败重试、截图/链接/日期验收差异和交付 manifest，按 `self-evolution.md` 提取候选。
2. flight、region、关注支路、个人偏好和文档链接只更新命中的日报子工作区；不能写进通用 skill。
3. 明确用户纠正，或已复现且修复通过质量门的通用方法，可在工作区标记 `skill-evolution=auto-authorized` 时直接最小更新本 skill，不再次请求批准。
4. 更新 skill 时必须同笔增加或更新 eval、脚本测试或可机器验收项；验证失败就修正或撤回本轮改动，不把未验证规则投入下一次自动运行。
5. 成功后更新 skill 的 evolution log、工作区 `skill-evolution.md` 和当天 manifest；没有可验证新经验时只记录“无可晋升项”，不为迭代而迭代。

## 链接索引写入规则

- 身份键是 `flight_id + link_type`；同一类型只保留一条当前权威 URL。
- URL 原样保存且可点击；同时记录最后验证日、窗口和特殊过滤条件。
- 报告链接允许结束日推进；开始日和固定过滤条件未经页面核对不得改变。
- 深度分析 query_id 会变化，以页面最新生成值覆盖索引当前值；旧值留在历史派发结果中。
- 新实验先写详情页；其余链接由子智能体逐类生成并回传，不借用其他 flight 的 query_id。

## 验收门

- 浏览器采集和截图均有当日子智能体派发留档；
- 主智能体未直接操作 Libra 页面；
- 关注 flight 与 watchlist 完全一致；
- 信号与展示日期和 watchlist 完全一致；特别检查“筛选入口 ≠ 信号”“实际生效日 ≠ 展示日期”；
- 每张图、每条 link 和每个数值都可追溯到 result.md；每张图同时记录像素收紧工具的输入/输出尺寸、`horizontal_fill` 和 `right_gap_px`；飞书图片 block 的显示宽高比与最终图相差不超过 1%；
- 中间指标截图已按 `flight_id + branch` 对账；`partial` 交付列出缺失支路、保留自动补查状态，未冒充完整验收；
- 图片发布重试已按 `parent_block_id + 最终文件名` 对账；文档回读中图片文件名全局唯一，无空白占位块和重复续传块；
- 每个中间指标支路使用独立图片路径，单图只含一个支路卡片，没有主路与目标支路长图；
- 链接索引已反映本次页面生成的最新 URL；
- 飞书日报、manifest、工作区记忆和自动任务互相不矛盾。
- 新建日报的链接权限已回读为 `tenant_readable`，且 `external_access=false`、`invite_external=false`；若用户明确选择其他范围，则记录并验收该范围。
- 自进化候选已完成判桶；自动晋升项有验证证据与 evolution log，未验证项只留在工作区候选队列。
