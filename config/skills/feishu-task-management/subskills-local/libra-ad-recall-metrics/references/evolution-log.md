# Evolution log

只记录已经通过验证并进入本 skill 的通用方法；任务专属事实留在对应工作区。

## 2026-08-03

- 用户未明确要求分人群时，日报默认使用未筛选 `user_tracking_status` 的全量口径；旧 T/NT 链接不能继承为主口径。
- 旧深度分析 URL 即使不含 `user_tracking_status`，页面配置仍可能保留显式 T+NT 过滤；全量查询必须回读筛选配置、删除该字段后重新提交并再次验收。
- 精准截图改为 DOM 初裁 + 像素级横向收紧 + 硬阈值验收；原始 DOM 图禁止交付。
- 飞书替换图片时同时更新 token 与按源图比例计算的显示宽高，避免去留白后的图片被旧尺寸压扁。
- 长期任务可通过工作区 `skill-evolution=auto-authorized` 授权，在每轮收尾自动判桶、验证并最小迭代本 skill，无需逐次批准。

## 2026-08-04

- 主报告与中间指标来自不同数据源时，最后完整数据日分别验证。中间指标必须在页面提交目标结束日并回读新生成查询；若结果回落到更早日期，日报分别标注两个截止日，不强行统一。
- 日报完成状态包含“文档回读验收 + 当日交付落盘 + 订阅群幂等推送”。只生成文档但尚未推送时，仍保留为待完成状态。
- Agent 新建的日报文档默认设为 ByteDance 内持链接可查看，并关闭外部访问与外部邀请；只修改这三个分享字段，重新读取权限确认后再交付链接。该方法已通过脚本单测与现有日报真实权限回读验证。

## 2026-08-05

- 用户新增或开启中间指标时，默认包含每个指定支路各一张精准截图，除非明确要求只要文字或 link。
- 日报不再用图片总数判断中间指标是否完整；按 `flight_id + branch` 生成覆盖 manifest。缺图可让其余内容以 `partial` 状态先发布，但必须列出缺失支路并继续补查，不能静默冒充完整验收。
- 关注实验、支路或展示偏好变更必须先写入命中日报工作区的 watchlist 并回读，随后才能回复已完成；聊天中的口头确认不能替代持久真值。
- 中间指标改为严格的一支路一图：不同 branch 使用独立图片文件，单图不能包含第二个 `queue_id`、`dpa_direct_id` 或事件卡片；覆盖校验会把复用同一图片路径标为 `partial`。
- 当任务工作区明确声明一组主报告日期同步时，日报先执行单哨兵日期探测；日期未推进就停止所有后续查数、截图和新文档生产，只复用上一期日报链接。未声明同步的任务不套用该捷径。

## 2026-08-06

- 单哨兵日期未推进且目标日期显示“数据产出中”时，这只是 `data_pending` 临时状态，不是 `no_data_update` 终态；停止本轮完整采集并延迟复查，复查仍无完整数据后才能复用上一期日报。
- 飞书图片发布重试必须先按 `parent_block_id + 最终文件名` 回读对账，只补缺失项；不得依赖列表切片续传。发布后验收图片文件名唯一、无空白占位块，再允许推送。
- 主报告日期哨兵未推进时，不能跳过已启用的中间指标日期探针。主指标与中间指标最后完整日独立记录；中间指标推进时必须回读页面生成的新链接并更新链接索引，不能继续复用旧 query。已验证：TTP `72201669`、`72218092` 的中间指标到 2026-08-05，2026-08-06 仍为产出中。
- 页面生成链接、最后完整日期、支路截图和飞书图片节点必须作为同一批次对账；只替换文字/URL 不算完成。中间指标每个 `queue_id`/`dpa_direct_id` 一支路一图，右侧空白做像素阈值检查；拆事件分析使用独立链接、独立默认折叠段，紧跟中间指标段，只有存在有效结果卡片时才放图。概述只保留主指标日期，其他日期留在对应折叠段。已验证：日报 revision `101` 回读 19 张唯一图片、4 个中间指标和 2 个拆事件段均 `folded=true`，新图右侧空白 0–8px。

- 中间指标发布前新增指标族身份校验。广告召回只接受 `ad_recall/Travel Recall/queue_id` 与 cid*req、独占消耗、总消耗字段；商品召回及 Combined PID 只接受 `product_recall/pid商品召回/dpa_direct_id` 与广告消耗、计费比字段。manifest 逐支路保存卡片标题和字段证据；错指标族、全量汇总卡代替指定支路或缺少身份元数据均标记 `partial`，不得按图片顺序补位。
