# 指标查看与归因流程

## 1. 主指标：ADVV 与 P-Value

入口：实验报告 → 广告报告 → Travel & Entertainment → Travel & Entertainment Catalog。

1. 使用最后完整数据日，确认 `l2_vertical_tag`、`is_search` 等过滤条件来自实验或权威链接。
2. 在第一张完整的 `T&E Catalog 实验指标` 表读取 `决策广告主价值Diff%`。
3. 点击 v1 的 diff 单元格，在浮层读取 `P-Value`、置信区间和累计 P 值曲线。
4. `p < 20%` 用于内部判断显著性；日报正文默认只写 ADVV 与 p 值，不自行补写“置信/不置信”。
5. 需要解释波动时，图表选择 `累计差异值` + `天级`，记录转折、收敛或回流，不用单日尖峰代替累计结论。

### 按用户 tracking 状态拆分

用户要求分 T/NT 查看时，在主报告过滤条件 `user_tracking_status` 中选择：

- `(0)可tracking`：T；
- `(1)不可tracking`：NT。

T、NT 必须分开点击“确定”执行查询，分别读取 ADVV、P-Value 和最后完整数据日；结果中明确写 `T` 或 `NT`，并保存页面生成的完整 URL。未选择该过滤条件代表全量，不能把全量结果当作 T+NT 两张分人群结果，也不能借用另一口径的截图或链接。

复用旧深度分析链接时，不能仅凭 URL 中没有 `user_tracking_status` 就判定为全量；页面配置可能仍保留显式 T+NT 过滤。默认全量查询必须回读筛选配置，若存在该字段则删除整行、通过页面控件重新提交，并再次确认筛选配置中已无该字段后，才验收页面生成的结果 URL。

禁忌：不能用 `广告主价值(opt)` 代替 ADVV，不能从单元格颜色猜 p 值。

## 2. 广告召回中间指标

入口：实验报告 → Ads Core → Cascade Ranking → `召回粗排` → `召回` → 深度分析。

模板选 `Travel Recall`，分组为 `queue_id`。常见主路口径以页面说明为准：

指标族不可互换：广告召回结果卡必须能看到指定 `queue_id`、实际通过召回的 cid*req（pass count）、支路独占消耗和支路总消耗；带 `dpa_direct_id`、广告转化量或计费比的卡片属于商品召回，不得用于广告召回实验。

- `-1`：T 主路；
- `-2`：NT 主路；
- `-98`：T+NT 合并主路；
- `-99`：全量。

这些负数值是常见的 T/NT/全量分组口径，不等于每个实验的业务主路。若命中任务工作区或实验文档明确记录某个正数 `queue_id` 为主路，以该任务真值为准；不得仅因 `-99` 表示全量就把它替换成业务主路。

目标支路至少读取：

| 指标 | 含义 | 判断 |
|---|---|---|
| 实际通过召回的 cid*req 数量 | pass count，进入粗排的量 | 低则问题先在召回覆盖/通过量 |
| 支路独占消耗 | 只靠该支路贡献的最终消耗 | 低说明不可替代作用小 |
| 支路总消耗 | 该支路参与的最终消耗 | 与独占消耗一起看覆盖和重叠 |

固定比较目标支路、对应主路和若干相邻支路：

- pass count 低、消耗也低：召回覆盖或通过量不足；
- pass count 高、消耗低：进入粗排但后续竞争力弱；
- 总消耗高、独占消耗低：与其他支路重叠较大；
- 独占消耗高：支路具备不可替代贡献，同时检查是否挤压其他支路。

分析输出顺序固定为“绝对量 → 相对变化 → 业务判断”：先列主路/支路的 pass count、总消耗、独占消耗及独占消耗率（或计费比），再计算各路由的绝对增量，最后说明新增/减少到底由哪一路贡献。若对照组为 0，页面显示的百分比涨幅是零基数结果，只能作为提示，不能描述为支路有效起量；只有绝对消耗和 pass count 同时达到可解释规模时，才可写支路承接或效率改善。

支路召回率常恒为 1，分支路优先看渗透率和消耗；不要用无意义的相对差替代绝对量。

## 3. 商品召回中间指标

入口：实验报告 → Travel & Entertainment → PCM业务大盘 → `PED真实转化` → 深度分析。

模板选 `pid商品召回`，分组为 `dpa_direct_id`，通常按广告消耗降序。

商品召回结果卡必须能看到指定 `dpa_direct_id`、广告消耗和计费比；带 `queue_id`、cid*req、支路独占消耗或支路总消耗的卡片属于广告召回，不得用于商品召回或 Combined 的 PID 分析。

核心指标：

- 广告消耗：支路实际作用规模；
- 计费比：`广告消耗 / 广告主价值(opt)`，越低效率越高；
- 广告主价值与转化量：帮助判断效率变化来自价值还是数量。

比较主路、目标支路和其他支路：

| 消耗 | 计费比 | 解释 |
|---|---|---|
| 高 | 低 | 规模和效率都强 |
| 高 | 高 | 起量明显，但单位价值成本偏高 |
| 低 | 低 | 效率好，但覆盖或作用规模有限 |
| 低 | 高 | 整体作用弱 |

对照为 0、实验组有值时，页面的 `+0%` 不表示“无变化”；使用实验组绝对值并与主路横向比较。

## 4. 转化事件拆解

入口同商品召回：PCM业务大盘 → PED真实转化 → 深度分析。

模板选 `Travel Catalog Event`，分组为 `external_action_en`，通常按广告消耗降序。对每种事件读取：

- 广告转化量；
- 广告主价值(opt)；
- 广告消耗；
- 计费比；
- 必要时补充发送、展现、点击和 CTR。

分析顺序：

1. 找对总 ADVV 贡献最大的事件，不按转化量排序直接判断价值。
2. 比较事件转化量 diff 与广告主价值 diff。
3. 粗算 `单次事件价值 = 广告主价值 / 广告转化量`。
4. 检查消耗增长是否慢于价值增长，并用计费比验证效率。
5. 解释事件 mix：高价值事件增加、低价值事件减少时，总 CVR 可下降而 ADVV 上升。

示例判断：某高价值事件转化量仅增长约 5%，广告主价值增长约 20%，说明价值增长不只是数量效应，还包含事件结构或单次价值提升。该结论是归因线索；需要进一步证明时继续拆事件属性或人群，不把它直接写成因果事实。

## 5. 跨页一致性

- 所有页面优先使用同一开始日和最后完整数据日。
- 不同数据源产出延迟不一致时，分别注明截止日，禁止把不同窗口的数值直接相减。
- 报告页、深度分析和实验详情中的 flight ID 必须一致；链接复用后先核对标题。
- ROW、TTP、EU 分开判断，不把跨机房绝对量直接比较成效果差异。
