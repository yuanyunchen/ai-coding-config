# 自进化闭环

本机制用于长期、自动运行的 Libra 召回实验任务。目标是同时维护两类长期资产：工作区保存具体任务真值，本 skill 保存跨实验可复用且已验证的方法。自动迭代不是无边界自改；授权范围只覆盖 `libra-ad-recall-metrics/` 目录和明确命中的任务工作区。

## 启用条件

- 当前对话中用户明确授权自动迭代；或
- 命中工作区 `MEMORY.md`/`memory/note/skill-evolution.md` 标记 `skill-evolution=auto-authorized`。

未命中上述条件时，仍总结候选，但按 harness-management 的常规审批门处理。hook、权限、凭证、AGENTS/CLAUDE、settings、其他 skill 和线上系统配置永远不在本授权内。

## 每轮输入

主智能体在日报交付或一次明确交互结束后检查：

1. 用户明确纠正、否定、格式要求或“以后都这样”；
2. 子智能体 `result.md` 中的失败、回退、重试和无法复核项；
3. 主智能体验收发现的日期、口径、链接、截图、折叠、数值或分类差异；
4. 工具退出码、硬校验指标和飞书回读结果；
5. 上一期与本期 manifest 中重复出现的人工修正。

每个候选写成五元组：`signal`、`root_cause`、`scope`、`change`、`verification`。没有根因或验证方法的观察不能直接晋升。

## 双桶判定

### 只写工作区

- flight、region、信号、展示日期、owner、支路和人群过滤；
- 关注开关、个人/群订阅、文档链接、日报样板和单次结论；
- 尚未复现的猜测或只对当前页面偶然成立的 workaround。

落点是命中日报子工作区的 watchlist、链接索引、决策、格式规范或 `skill-evolution.md`，不得污染通用 skill。

### 可晋升到本 skill

- 用户明确表达的长期方法或质量标准，一次明确反馈即可晋升；
- 可稳定复现的执行失败，且修复已通过机器验收或飞书/Libra 回读；
- 两次独立运行都出现的同类低效步骤，并有更短且等价的验证路径；
- 能转成硬校验、脚本、eval 或明确流程门的通用经验。

不能验证、只改善措辞偏好或可能削弱安全边界的内容不自动晋升。

## 自动更新步骤

1. 完整读取本 `SKILL.md`、候选命中的 reference/script/eval 和 `evolution-log.md`。
2. 查重与冲突：用户最新明确反馈优先；若旧规则冲突，原地替换，禁止新旧并存。
3. 采用最小改动：高频硬门放 `SKILL.md`，低频流程放 references，机械缺陷优先修脚本，触发回归补 eval。
4. 去任务化：skill 中不写用户姓名、群 ID、flight、具体链接、token、日期或单个报告结论。
5. 验证：至少运行 JSON/语法检查和新增的针对性测试；涉及截图还要保存像素指标，涉及飞书还要回读 block，涉及分类还要检查工作区真值未被覆盖。
6. 验证失败时，用最小补丁修正或撤回本轮新改动；把候选与失败原因留在工作区，不更新成功日志。
7. 验证成功后，在 `evolution-log.md` 追加一条短记录，并更新工作区最近成功迭代与当天 manifest。

## 防漂移规则

- 不为“看起来更完整”增加用户未要求的指标、类型、截图或分析。
- 不把一次任务偏好升级成所有用户的默认；只有方法与质量门可通用化。
- 不降低只读、权限、身份隔离、幂等和主/子智能体分工边界。
- 不自动修改其他 harness 对象；需要跨 skill 或全局变更时恢复正常审批流程。
- 没有新候选时保持文件不变；自进化的成功标准是减少同类返工，不是增加规则数量。

## 工作区记录格式

```markdown
## 最近一次运行
- 时间：YYYY-MM-DD HH:mm TZ
- 反馈/差异：...
- 判桶：workspace | skill | no-op
- 改动：...
- 验证：...
- 状态：promoted | queued | rejected | none
```
