# 策略算法 ASCII 框架图专家

## 目的

把一套复杂的算法、策略或业务链路，画成一张高可读性的 **ASCII 纯文本全景框架图**。读者看完应当能一眼看懂：原始输入是什么 → 每一步由哪个过程/公式转化 → 不同阶段之间如何流转与复用信号 → 最终输出/结算怎么算出来。图就是文档本身，不需要额外口头解释。

> **ASCII 是首选、不是兜底。**(权威选型矩阵见 [`lark-doc-writer §0.6 作图选型矩阵`](../lark-doc-writer/SKILL.md)。)凡**公式化 / 多阶段策略·竞价·计费·排序·定价·风控·出价调控链路,或需等宽精确对齐、同名变量分身**,本 skill(ASCII 进 `<code language="text">`)就是首选——它把逐阶段公式推导讲得最清楚,等宽精确对齐,且**永不被压成瘦高竖条**(mermaid→PNG 的线性流常踩这个坑)。一篇讲"公式驱动的多阶段链路"的文档**应当至少包含一张 ASCII 策略图**;不要把所有图都做成 PNG。纯线性短流(`A→B→C`)同样 ASCII 比 PNG 稳。需要图形化分支/泳道时才转 `dag-flow-diagram`→PNG。
>
> **分工 + 每节双图里 ASCII 的角色(与 [`lark-doc-writer §0.6`](../lark-doc-writer/SKILL.md) / [`dag-flow-diagram`](../dag-flow-diagram/SKILL.md) 同口径)**:**DAG = 框架 / 概念关系 / 全景 / 总结(高层鸟瞰),ASCII = 细节 / 公式链路逐步展开(逐阶段推导、同名变量换分身)**,两者分层不互斥。learning 文档每节用**双图配合**讲一个逻辑——DAG 出关系/依赖骨架,**本 skill 出那张「公式逐步细节」**,文字只解释。在「开篇导览 DAG → 正文双图 → 结尾双收口」骨架里,本 skill 负责**正文的细节公式图**与**结尾双收口的「全链 ASCII」**(从最原始输入一路画到最终结算/反哺的完整逻辑图,即下「范例二」那种全景链路);结尾的总结 DAG(变量依赖网)由 `dag-flow-diagram` 出。⛔ 不用 ASCII 当开篇全景(高层概念关系是 DAG 的活)。

动手前先把端到端链路想清楚：有哪些实体、哪些"同名不同值"的变量分身、分几个阶段、有哪些跨阶段复用的信号。具体怎么排版，照着 [`references/examples.md`](references/examples.md) 的两个范例来即可（动笔前必读）。

## 基本原则

- **流程完整**：从最原始输入（出价、原始请求…）一路画到最终输出/反哺（最终扣费、回写模型…），不断链、不跳步。
- **实体即对象**：每个节点都是 `[ 对象 ]`（数据/信号/参数/模型/结果），用标准术语 + 中文解释 + 单位标注；**同名不同值**的变量拆成独立实体（如 `pCTR_rank` vs `pCTR_charge`），不要混用。
- **边即过程**：连线讲"怎么算"（命名过程或纯文本公式），框里放"算出什么"；公式只用普通字符，不用 LaTeX。
- **单主干、就近引用**：全图一条主干自上而下；跨阶段复用的信号在产出处分出、在消费处就近引回，不拉贯穿全图的右侧竖轨；回路用一句文字回指。
- **无凭空变量（闭环）**：每个自变量必须由有身份的外部对象供给（广告主定义 / 系统预测 / 调控模块 / 用户），外部对象要画出来并标明身份，不写"(自变量来源)无入边"。因变量必须由 自变量 + 公式/算法模块 引导得出，不跳步。系统中不出现无来源的变量（如 convert 要标明来自被广告展现的用户）。
- **完整体现系统逻辑**：一张图尽量含支路、中间变量、评估指标，不让读者自己拼。
- **分层展示**：按图的作用调整细节程度 —— 概述图展示高阶段过程（隐藏底层细节），具体模块图展开细节；复杂框架优先用 ASCII（而非压缩的 mermaid）解释逻辑。
- **行宽封顶 ≤ ~72 显示列，且每个中文/全角字符按 2 列计（强制，否则飞书代码块右切）**：飞书 Code 块在标准宽度下大约 **80 列**就到右边界，**超宽的行在文档加载时 / skim 时 / PDF 导出时右侧尾部会被裁掉**（要在块内横向滚动才看得到，visual_qa D1 实测：带长中文尾注的公式行、整行 `=====` 分隔规则最容易超宽被切）。所以**任何一行的显示宽度都不要超过 ~72 列**（留出余量,别贴 80 顶格）。**关键：宽度按"显示列"算，不是按字符数 —— 每个中文/全角字符（含「」『』（）：，、。等全角标点）占 2 列，ASCII 字母数字与框线字符 `▼ │ ─ ► ◄ ★ ┌ ┐ └ ┘ ├ ┤` 各占 1 列。** 因为一行里中文越多、它的显示宽度比字符数膨胀越快(36 个中文就已 72 列顶满),所以**含大量中文的行 ≈ 最多 36 个汉字**就要换行。具体：
  - **长中文尾注另起一行**：把 `>>> …` / `<-- …` 这类跟在公式/实体后面的长中文解释，从主行**移到下一行**（缩进对齐到被注释项下方），不要和公式挤在同一行把行撑爆。例：`[ rank_bid ] = cpa_bid * coef * pCVR_rank （元/点击）` 单独成行，其后另起一行写 `        >>> 锁定为"点击限价",计费阶段还要回头比对`。
  - **长中文说明分多行**：`★【… 阶段】` 下的整句中文说明、节点后的长括注，超过 ~36 汉字就在自然停顿（逗号/顿号）处断行，续行缩进对齐到说明首字下方。
  - **深缩进的支链拉回主干**：分支（IF/ELSE）里若把后续整条链路越缩越右，缩进本身就会吃掉几十列、再短的节点也溢出 —— 让分支只产出它的结果节点，随后**回到主干列**继续往下画（单主干原则），不要把主链挂在右侧深缩进处。
  - **`=====` / `━━━` 分隔规则按 ~72 列截**：阶段分隔横线别拉到 80+ 列(否则它自己就溢出右切),控制在 ~72 列内（72 个 `=` 正好顶满）。
  - **写完按显示列自检最长行 ≤ ~72**：心算靠不住时，用一段按 CJK=2 计宽的小脚本扫一遍最长行（见本文件末「自检脚本」）。

## 格式速查

每种写法表示什么（具体排版照 references/examples.md 的范例）：

| 写法 | 表示 |
|------|------|
| `[ name ] (单位) 中文` | 一个实体对象 |
| `│` / `▼` | 主干流向，`▼` 指向下一个实体 |
| `│` 旁一句话 | 这条边的过程或公式（怎么算的） |
| `★【名称 阶段】` | 由某命名系统/服务负责的重要阶段（Arbiter / GSP / Cypher…） |
| `IF ( 条件 ) … ELSE ( … )` | 分支：截断/择优/降级，各分支指向自己的 `[ 结果 ]` |
| 产出 `├──► [ 信号X ]`；消费 `◄── 注入 [ 信号X ]` | 跨阶段信号的就近引用 |
| 整行 `=` 包裹 `【第N阶段：…】` | 切分大阶段 |
| 分子 / `─` / 分母 三行 | 纯文本分式（替代 LaTeX 的 `\frac`） |

> 对齐靠等宽字体：中文/全角符号占 2 列、ASCII 与 `▼` 占 1 列；按显示宽度对齐，主干竖线尽量落在同一列。

## 输出

按产物去向选落地形式:

- **用户明确要求图进飞书文档或任务已有明确飞书目标→ 落进 `<code language="text">` 块(Code(14))**:这是 ASCII 图在飞书的标准落地形式,等宽渲染、随处可用,也是**任何图的始终可落地的文本兜底**(本租户实测:Code(14) 块 create 稳定成功,而 `<whiteboard>`/原生 Diagram 经飞书 API(lark-cli)都做不出真画板)。走飞书 XML 导入路径时,**代码块内所有 `<` `>` `&` 必须先转义**(见下);走 block API(JSON,`block_type 14`、`style.language` 用 PlainText/Text)时**无需转义**(`lark-doc-writer/references/mcp-recipes.md` 配方3)。
- **需要一张"渲染成图"的可视化(而非纯文本)时**:本机无法把 ASCII 变成原生画板;若确需图形化,改用 `dag-flow-diagram` / `chart-gen` 出图后**渲染成 PNG 嵌 Image(27) 块**(mcp-recipes 配方3 / media-embed 管线)。ASCII code 块本身已是高可读的等宽图,多数链路用它即可。
- **只在对话里展示(不落飞书)**:整张图包在 ` ```text ` 代码块里(裸放在正文会被 Markdown 破坏对齐)。代码块上方可加一行标题与极简图例,下方可补几句关键结论。

飞书 XML 导入路径的转义:否则飞书会把 `<` 当标签起始、吞掉后续直到下一个 `>` 的全部内容,导致大段静默丢失:

| 原字符 | 转义为 |
|---|---|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `&` | `&amp;` |

高发场景：比价分支 `IF ( eCPC_B <= rank_bid )`、阈值判断 `sorted_ecpm < EcpmThresh`、`<-- 赢家`、`< 30%`、健康区间 `cost_ratio < 1.2`。写入前自检：`<code language="text">` 块内裸 `<` / `>` 应为 0（`&lt;`/`&gt;`/`&amp;` 不算）。`▼ │ ─ ► ◄ ★ ━` 是普通 Unicode 字符，不需转义，只有 `< > &` 要转义。

**写入前第二项自检（行宽，visual_qa D1）**：算每行的**显示宽度（每个中文/全角字符 2 列、ASCII 字母数字与框线 `▼ │ ─ ► ◄ ★ ┌ ┐ └ ┘ ├ ┤` 各 1 列）**，**最长行 ≤ ~72 列**。超 72 列的行 = 飞书代码块加载时右尾被切（要横向滚动才看得到，PDF 导出也丢）。修法见上「行宽封顶」：长中文尾注 `>>> …`/`<-- …` 移到自己的续行、长中文说明在逗号处断行、深缩进支链拉回主干、`=====` 分隔截到 ~72 列内。

## 自检脚本（行宽，CJK=2）

写完图后、写入飞书前，把图文本喂给下面这段，确认 `max width` ≤ 72、`lines > 72` 为 0（心算中文宽度极易漏，务必跑一遍）：

```python
import unicodedata
def dwidth(s):
    return sum(2 if unicodedata.east_asian_width(c) in ('W','F') else 1 for c in s)
ascii_art = """  # ← 把你的 ASCII 图整段粘进这里
"""
mx, over = 0, []
for n, ln in enumerate(ascii_art.split('\n'), 1):
    w = dwidth(ln); mx = max(mx, w)
    if w > 72: over.append((n, w, ln))
print('max width:', mx, '| lines > 72:', len(over))
for n, w, ln in over: print(f'L{n} w={w}: {ln}')
```
