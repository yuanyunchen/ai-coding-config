## 二、统一版式(四种原型共用,换内容不换骨架)

```
┌ 标题 27/600  ────────────────────────────────  图例(右上,色块 + 一句语义)
│ 副标题 14.5   ← 一句话结论,不是"本图展示…"
├──────────────────────────────── 分隔线 #E6E2DB
│ 列/段小标 12.5/600 #9AA5AB letter-spacing 1.2(「公 共 上 游」这种疏排)
│
│ 主体:卡片 rx=10、1.4px 描边、语义填色;正交折线走线(H→V→H),labels 贴段
│
├ 横切/共同项:整宽 dashed stone 带(与主体实色块区分)
└ footer 11.5 #9AA5AB ← 来源 + 哪些数是示意/待确认(可溯源,不虚标)
```

- **边距**:左右 48;卡片间横向 gutter ≥ 90(要放边标签),纵向 gap 24。
- **owner 编码**:卡片左侧 4px 色条 + 右上姓名 pill(圆角 9、实底白字)。同一人全图同色,图例里点明。
- **数量用长度表达**:量级条 / quota 条 / 覆盖率条 —— 比写数字更快被读懂;条内文字放得下就放内部(白字),放不下移到条右侧。示意比例必须在 footer 声明"非实测占比"。

**受限 / 待定一律走 amber**,并且图里出现 amber 就必须在 footer 或卡内说清"待谁确认"。

## 四、字号闸(与 SKILL.md「布局与长宽比」同为硬闸)

飞书正文列约 **700px**;1160 逻辑宽的图显示时缩放 ≈ **0.61**,逻辑字号乘 0.61 才是读者看到的像素。

| 角色 | 逻辑字号下限 | 显示约 |
|---|---|---|
| 图标题 | 27 | 16px |
| 副标题 / 卡片标题 | 13.5 – 15 | 8.5 – 9px |
| 卡片正文 / 边标签 / 图例 | **≥ 11.5** | ≥ 7px |
| footer 溯源行 | 11.5 | 7px |

**实测教训**:第一版把卡片正文写成 10.5,在飞书里只有 ~6.4px,肉眼吃力 → 统一上调一档后可读。**逻辑字号 < 11.5 一律不许出现**;放不下就删字、拆图、或加大画布高度,不许缩字。

## 五、渲染 + 自检(照做)

`../templates/render_svg.sh`(直接抄):把 SVG 包进 HTML 再用 headless Chrome 截图,`./render_svg.sh <name> <w> <h> [scale=2.5]`,同时打印尺寸与 w/h 供过闸。

```bash
"$CHROME" --headless --disable-gpu --hide-scrollbars --screenshot="$N.png" \
  --window-size=$W,$H --force-device-scale-factor=2.5 "/tmp/_wrap_$N.html"
```

- **`--force-device-scale-factor=2.5`**(不是 2):1160 × 2.5 = 2900px,飞书里点开看原图清晰,列宽内也不糊。
- **CJK 字体钉死** `'Hiragino Sans GB','PingFang SC',sans-serif`。
- **渲完必须自己 `Read` 看 PNG**,逐条查:① 文字有没有溢出卡片右边界(CJK 宽 ≈ 字号、拉丁 ≈ 0.55×,估长后仍要看);② 边标签有没有压在连线上(压了就挪到线段的另一侧,或给标签垫一块底色 rect);③ 同一 rank 的卡片顺序是不是读者期望的顺序;④ w/h 过闸。**盲渲必踩前三条**。
- 手绘 SVG 没有自动布局,**同排卡片顺序 = 你写坐标的顺序**;要 A/B/C 从左到右,x 坐标就按序给,别指望渲染器纠正。
