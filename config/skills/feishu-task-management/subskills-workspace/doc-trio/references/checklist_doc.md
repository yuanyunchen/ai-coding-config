# checklist 写作规则(checklist doc)

> **文档定位**:把多份零散资料(原始平台文档、mentor 逐字稿、代码、AI notes)整合成一份**有依赖顺序的学习路径待学清单**,给人按路径学。读完应当知道:整条路径长什么样(谁是谁的前置、哪些可并行)→ 要学哪些知识块 → 每块按什么顺序读哪些资料 → 每份资料看它的哪一章、解决什么问题。
>
> **典型场景**:新人 onboarding 待学清单、某方向的学习路径、1:1 后整理的待学知识。
>
> **与学习文档的区别**:学习文档是"把一个系统讲清楚"(自产内容为主);checklist 是"把多份资料组织成依赖有序的学习路径"(导航 + 整合为主)。
>
> **与操作指南的区别**:操作指南是"照着做能跑通"的时序 SOP;checklist 是"按路径学会知识"。
>
> **写作通则**:命名 📖、格式、去 AI 化风格、Callout 节制、可读性、作图选型以 `lark-doc-writer` §0 为唯一权威,本文件只写 checklist 专属规则。
>
> **配套模版**:`templates/checklist_doc.xml` —— **照搬用户参考 checklist 版式**的可复用骨架(版式权威 = `phase4/discovery/reference_spec.md` §checklist「照搬目标」,题材抽象掉)。直接复制 → 替换业务专属内容,骨架 / 章节顺序 / 开场三连 / 依赖图 / 节级 callout 四件套 / checkbox 保留。
>
> **版式照搬要点(参考 checklist 的真实形态)**:开场三连 callout(蓝 📖 概述 → 橙 📎 Context → 绿 💡「学习路径」引图)→ 开头一张依赖全景图 → 8 个一级节,**每节统一三件套**:`H1 → 一个浅黄节级 callout(收【定位】【核心问题】【⭐优先读】【学习顺序导读】四件)→ 节外真 checkbox`。**全篇 0 表格、0 ASCII(那张依赖图除外)**,分组靠 callout 项目符号 + checkbox 承载。
>
> **本机飞书侧适配**:① 依赖全景图(参考是可拖拽画板)本机出不了原生画板 → **首选渲 PNG 嵌 Image(27),ASCII 进 code 块兜底**(`<whiteboard type="mermaid">` 经飞书 API(lark-cli)被拍平、不出画板,实测)。② callout 图标经 **create-time 原始 REST 设 `emoji_id`**(`lark-doc-writer/references/mcp-recipes.md` §配方1:飞书 API 建 callout 无 `emoji_id` 字段、落默认 🎁,事后 patch 报 1770001;已验证 map `book`→📖 / `bulb`→💡 / `paperclip`→📎 / `memo`→📝,⛔ 不用未验证的 `page_facing_up`);**正文不放前导 emoji**(否则双图标)。

## 一、结构骨架(依赖有序)

```
开场三连 callout(顺序固定):
  蓝色概述框(📖,整体介绍 + 按学习顺序列各知识块一句话)
  橙色 Context 框(📎,原始文件 link + 一句简介 + 元信息)
  绿色「学习路径」引图框(💡,一句话引出下面那张依赖全景图)
开头依赖全景图              ← 紧跟绿框,看清整条路径再开学
  - 块 / 阶段为节点 + 带标签箭头 + 并行块并排(谁是谁前置 / 哪两块可并行 / 哪块回收闭环)
  - 本机飞书侧适配:首选渲 PNG 嵌 Image,ASCII 进 code 块兜底
  - 一句话点出唯一不显然的排序点(避免读者误判为断层)
8 个一级节,每节统一三件套(节数按主题增删):
  H1 {知识块标题}
  一个浅黄节级 callout(memo,bg=7 浅黄底 / border=7 边)收四件:
    【定位】为什么学 + 在路径里的作用 + 前置 / 并行 / 闭环关系
    【核心问题】学完要能回答什么
    【⭐优先读】指向配套学习文档,一句话说它整合了什么
    【学习顺序导读】有序列表,每条先说「看什么」再定位到目标文档最低层级章节
  节外真 checkbox(<checkbox done="false">)列「学什么」,每条写清学到什么程度
覆盖 gaps 与延伸方向        ← 浅黄节级 callout:声明主链 + 项目符号列相邻话题(不展开,只给跳转)
术语速查                   ← 浅黄节级 callout:项目符号列术语工程口径,口径分歧处取正确口径并注明
```

> **照搬版式 vs 内容组织**:上面的「开场三连 / 节级 callout 四件套 / checkbox / 0 表 0 ASCII」是**参考 checklist 的版式**,照搬;下面 §二~§七是**内容怎么组织**(依赖排序、导读写什么、取材纪律),与版式正交。两者都要满足。

> **依赖有序是 checklist 的灵魂**:知识块不是平铺罗列,而是按**依赖关系**排序 —— 地基块在前,被多块共用的"公共尺"块次之,互不依赖的块标为可并行,回收偏差的块收口在后。开篇的依赖关系图把这条路径画出来,是 checklist 与"资料清单"的本质区别。

## 二、依赖关系图(checklist 专属,强制)

- **开篇先放一张依赖全景图**,紧跟绿色「学习路径」引图框、在所有一级节之前,让读者先看清整条路径再开学。
- 图里必须表达三件事:**块 / 阶段为节点 + 前置依赖带标签箭头**(箭头 = 学完前者再学后者,标签写传递了什么 / 为何先后)、**可并行的分支并排**(互不依赖的块横向并列,虚线泳道可选)、**回收闭环**(后块的某定义回灌前块,画回环箭头)。
- 线性主题(无分支无闭环)可简化为一条链;但**只要存在并行块或回收闭环就必须画出来**,否则读者会把"非线性依赖"误读成断层。
- **本机飞书侧适配(参考是可拖拽画板,本机出不了原生画板)**:**首选渲染 PNG 嵌 Image(27) 块**(mermaid / graphviz 出源见 `dag-flow-diagram`,PNG→Image 管线见 `mcp-recipes.md` §配方3;长宽比 / 尺寸闸见 dag-flow-diagram);**ASCII 进 Code(14) 块兜底**(渲不出时),每行显示宽 ≤72 列(CJK 计 2),走 XML 导入时 `< > &` 转义。⛔ 不用 `<whiteboard type="mermaid">`(经飞书 API(lark-cli)被拍平、不出画板,实测)。
- 图后补**一句话点明唯一不显然的排序点**(例:"块4 看似最后,但块3 的偏差源在块4 定义,所以块4 收口而非续接")。把"需要解释的依赖"写明,是 gap-free 路径的关键收口。

## 三、视觉分区:节级 callout + 节外 checkbox(checklist 专属,强制 —— 照搬版式)

参考 checklist 的视觉分区不是「稍灰字导读」,而是**每个一级节一个浅黄节级 callout**收齐导读四件、callout 之外才是真 checkbox:

- **每个一级节固定:`H1 标题 → 一个浅黄节级 callout → 节外真 checkbox`。**
- 节级 callout = `memo`(📝)、**bg=7(浅黄底,light-yellow)/ border=7(yellow)**,经 create-time 原始 REST 设 `emoji_id`(配方1,已验证渲染正确);**正文不放前导 emoji**。它把「这是导读」整体框起来,与节外「要学什么」(checkbox)天然分区,比靠字体颜色更强。
- **0 表格、0 ASCII(那张依赖全景图除外)**:分组 / 层级靠 callout 内项目符号 + 节外 checkbox 承载,不用表、不用 ASCII 罗列。
- 不在节里再堆别的高亮框;一个节就一个浅黄 callout + 若干 checkbox,密而不挤(靠配色分区 + checkbox 留白)。

## 四、每个一级节的三件套(checklist 专属,强制 —— 照搬版式)

每个一级节固定三件:**H1 标题 → 一个浅黄节级 callout(收四件)→ 节外真 checkbox**。

### 4.1 节级 callout 收四件(每件粗体 label 起头)
浅黄节级 callout 内按固定顺序收齐:

- **【定位】**:为什么学这块(它在路径里的作用)+ **前置依赖**(必须先学完哪块);后置 / 并行 / 闭环关系一句话点明,与依赖图呼应。
- **【核心问题】**:学完本块要能回答的 1~3 个问题(结论先行,不空泛)。
- **【⭐ 优先读】**:指向**配套学习文档**的具体章节,一句话说它整合了什么 —— checklist 不在节内重复正文,系统原理交给学习文档,这里只做导航(必要时加「📌 待补权限」)。
- **【学习顺序导读】**:有序列表(`<ol>`),按**阅读顺序**排、**每个文档一条**;每条**先说目的**(建立 / 补充 / 加深 …)→ **再定位到目标文档最低层级章节**(不让读者二次跳转)。

学习顺序导读格式样例:
```
1. 先读 [文档A](url) —— 目的:建立 XX 直觉。看它的「§2 整体流程」。
2. 再读 [文档B](url) —— 目的:补充 YY 细节。看它的「§3.4 N 步流程」。
3. 加深:[文档C](url) —— 目的:理解 ZZ 为什么这么设计。看它的「§4 调参方向」。
```

### 4.2 节外 = 学什么 todo 真复选框
- callout 之外用 **todo 列出「学什么」**:每条一个可勾的学习目标,写清「学到什么程度」(如"能说清 A 与 B 的分工边界"),不空泛;已学项 checked + 删除线。
- XML 用 `<checkbox done="false">`,**不要用表格 + ☐ 字符**(渲染才是真复选框,QA 验证点)。

### 4.3 整合内容交给配套学习文档(不内联、不用表)
- 照搬版式下 checklist **以导航为主**:每节的「⭐ 优先读」指向配套学习文档,系统原理 / 公式链路 / 枚举对照都放在那篇里,checklist **不内联整合正文、不用表格**(参考 checklist 全篇 0 表)。这样 checklist 保持轻、可勾、是「学习路径」而非「资料堆」。
- 若某主题确无配套学习文档、地基必须就地讲清:也**优先用节级 callout 的项目符号**承载要点(结论先行),仍不引入表格 / ASCII 罗列;真要画链路图则按 §二 走 PNG / ASCII 兜底。

## 五、覆盖 gaps 与术语速查(强制)

### 5.1 诚实的 gap-fencing
- 末尾设「覆盖 gaps 与延伸方向」节:**显式声明本清单聚焦哪条主链**,把与主链相邻、但**刻意不展开**的话题列出来,每条一句话说明为什么不展开 + 给跳转章节。
- 这是 checklist 的反堆砌纪律:相邻话题只给指针,不把原始材料拖进来(否则退化成资料堆)。

### 5.2 术语速查
- 末尾设「术语速查」节,把主线里的关键术语给出**工程口径**(一句话讲清 + 必要公式)。
- **照搬版式:用浅黄节级 callout + 项目符号承载,不用表格**(参考 checklist 全篇 0 表);「覆盖 gaps」节同样用浅黄 callout(声明主链 + 项目符号列相邻话题 + 跳转)。
- **口径分歧处取正确口径并注明**:若某术语在不同源定义冲突,这里取正确口径呈现,并一句话注明"此处取 X 口径,因为 …";**不要在文内留两个并存定义让读者困惑**(常见反模式:同一变量在术语速查与正文公式里形式不一致而无说明)。

## 六、取材质量(checklist 是典型的 search→organize→write)

checklist 的核心是"把搜到的多份资料组织成依赖有序的学习路径",写之前先按 `lark-doc-writer` §0.7 把取材做扎实:
- **覆盖性**:按 perspective-templates 该类型视角(K1/K2/U2/U3)核对该讲的角度有没有都搜到,缺角补搜。
- **可信度**:优先主源、注时效、多源交叉、单一来源标注。
- **综合而非拼贴**:同主题多份资料**融成连贯的统一主线**(一条贯穿的变量 / 概念线),不逐份摘抄堆叠。Context 框里每个源给一句简介 + 可跳转。

---

## 七、不放原始材料(强制)

- checklist **只放整合后的学习路径与导航**,不堆原始材料(原始文字记录、细节代码)。原始材料归原始素材目录或 AI handoff。

---

## 八、引用规则

- 文档介绍里的跳转用 `[文档标题](url)`(链接即内容,不用 `[[..]]` 引用样式)。
- 整合内容里的事实 / 数值句末用 `[[标题]](url)` inline 引用。
- 区分出处类型:mentor 逐字稿 / AI notes / 原始平台文档 / 配套自产文档。
