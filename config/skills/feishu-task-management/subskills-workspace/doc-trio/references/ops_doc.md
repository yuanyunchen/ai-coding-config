# 操作指南 写作规则(ops doc / SOP)

> **文档定位**:把一个流程从第一步到最后一步**按真实操作时序**写出来,让接手者照着做能跑通,不需要再翻原始资料、不需要再问 owner。
>
> **典型场景**:实验复制 / 复盘流程 / 部署 SOP / 上线 checklist / 平台操作指南。
>
> **写作通则**:命名 / 格式 / 去 AI 化风格 / Callout 节制 / 可读性以 `lark-doc-writer` §0 为唯一权威。
>
> **配套模版**:`templates/ops_doc.xml`(算法实验类骨架,跨业务可直接复用)。

---

## 一、结构骨架(按操作时序)

```
一、相关文档(背景文档 / 原始平台指南 / meet note,inline URL)
二、Blocker checkbox(提前 callout,5 个左右关键卡点)
三、参数对照(改前 / 改后 / 流量百分比)
四、平台 1(如 Libra)— 第 1 步到第 N 步
  4.1 入口 URL
  4.2 按钮路径
  4.3 字段名 + 具体取值(不写"按需填写")
  4.4 成功/失败判定
五、平台 2(如 Omega)— 引流 / 自测
六、平台 3(如 Grafana / 监控)— 关键 metric 列表
七、Review 流程(谁、什么时候、备份 reviewer)
八、放量节奏(0.1% → 1% → 10% → 33% 的时点 + 卡点)
九、中间指标(平台路径 + 阈值)
十、结果指标(平台路径 + 阈值 + 决策准则)
十一、决策准则(现象 → 行动)
十二、时序图 / 总览(mermaid)
```

可裁剪:非实验类 SOP 可删 §三、§八、§九、§十;但 §一(相关文档)、§二(blocker)、§四~§六(平台操作)、§十一(决策)必须保留。

---

## 二、核心硬规则

### 1. 严格按实际操作时序
- 从打开第 1 个平台开始,到最后一步结束。
- 不要先讲理论后讲操作 —— 理论归学习文档,这里只讲"做什么"。

### 2. 每步必含 4 件套
- (a) 平台 URL(可点的 inline 链接)
- (b) 按钮路径(具体到"点 X → 点 Y → 填 Z")
- (c) 字段名 + **具体取值**(不写"按需填写"、"看情况";给默认值或决策表)
- (d) 成功 / 失败判定标准(看到什么算成功;失败找谁)

### 3. 不让用户翻原始文档
- 相关信息 inline 写进步骤里。
- 原始指南只在 §一"相关文档"里出现一次 URL,供回查;具体字段、取值不要说"详见 XX 文档"。

### 4. 预计 blocker 提前 callout/warning
- 哪些坑(权限不够 / 红线时间 / 平台 bug)
- 卡在哪(具体步骤 + 现象)
- 找谁(联系人 + 群)
- 放在文档开头 §二,不要散落到正文里。

### 5. 开头声明关联文档
- 背景 / 原始指南 / meet note / AI handoff,inline URL 必给。
- **无内部 source 的 from-scratch SOP**(任务没给内部原始文档,如从零搭一套环境):Context / §一相关文档**引上游官方文档的真实 URL**(如官方 replication/sentinel 指南、Docker Hub、Compose 参考),措辞为"参考资料",**不编造内部文档链接**(R11)。这与"相关文档=背景/原始平台指南/meet note"的常见场景不同,引权威上游即可。

## 三、措辞规则

### 禁用
- 口语化引导:"跟着步骤一步步做"、"我们来看一下"、"咱们"
- 元说明 / 读者指引:"本文目标"、"如果你..."、"读者可以..."、"不熟悉可跳过,需要反查时再看"
- 冗余 callout 解释文档结构本身

### 推荐
- **动宾短句**:"打开 Libra → 复制实验 → 改这 6 个字段:..."。
- **表格 > 段落**:字段对照、参数改动、决策准则一律用表。
- **截图位置预留**:关键步骤可放 `<p>SCREENSHOT_PLACEHOLDER_X</p>`,后续用 `drive_v1_*` 上传截图、再以 `docx_v1_documentBlock_*` 把图片块替换进对应位置。
- **inline 引用出处**:`[[平台指南]](url)`,放在事实陈述的句末。

## 四、Blocker callout 标准格式

```xml
<callout emoji="⚠️" color="orange">
<p><b>开干前确认这 5 件事</b>(任一未确认会卡):</p>
<ul>
  <li>[ ] 权限:{所需角色 / 群},不在 → 找 {人}({群})。</li>
  <li>[ ] 红线时间:{机房 + 时段},红线内开实验必须走 {审批群}。</li>
  <li>[ ] 关联文档:背景 {url} / 原始指南 {url} / meet note {url}。</li>
  <li>[ ] reviewer:主 {人},备份 {人}。</li>
  <li>[ ] 测试环境:{平台} 实例可用、TTL 充足。</li>
</ul>
</callout>
```

## 五、参数对照标准格式

```xml
<table>
  <tr><th>版本</th><th>改动 key</th><th>改前</th><th>改后</th><th>流量</th></tr>
  <tr><td>V0</td><td>—</td><td>—</td><td>—</td><td>隐式 baseline</td></tr>
  <tr><td>V1</td><td>{key}</td><td>{old}</td><td>{new}</td><td>33%</td></tr>
  <tr><td>V2</td><td>{key}</td><td>{old}</td><td>{new}</td><td>33%</td></tr>
</table>
```

## 六、决策准则标准格式

```xml
<table>
  <tr><th>现象</th><th>决策</th><th>调整动作</th></tr>
  <tr><td>{指标症状}</td><td>{继续/调参/停}</td><td>{具体改哪个 key:从 X → Y}</td></tr>
</table>
```
