# 周会整理 Note 模板(三段式 · weekly_review)

> 把一次周会整理成可复用、可执行的 note。落地走 block API(参考 2026-06-17 周会 Note 实现),非 XML 导入。
> 写作通则以 `lark-doc-writer` §0 为唯一权威;本模板只定**三段骨架 + 本类型专属硬规则**。

标题:`📖 {{我}} × {{对方}} 周会 Note · {{日期}}`

- **蓝色概述 callout(📖 book)**:一句"本篇按三段组织" + 3 条 bullet(知识总结 / 待办清单 / 路线图,各一句)+ 主线一句。
- **橙色 Context callout(📎 paperclip)**:来源(文字记录 / 智能纪要 / 妙记),各带可点链接 + 一句简介。

## 一 · 知识总结(我补到的认知)
> **只记我原先不会、别人讲 / 纠正的点**;我自己已掌握的系统全链**不复述**(开头一句"系统全链我已掌握,这里不复述",指向相关学习文档即可)。
- 每点:**H3 名词短语标题**(⛔ 不加「—— 我漏了 X / XX 带着推 / 我答成大盘」这类自述后缀)→ 一句「我原以为…实际…」要点 → **聚焦小图**(只画这个新点,不画全链)→ 相关文档。

## 二 · 待办清单
> 先总览图,再分主题,每主题 checklist + 图 + 相关 context。
- **总览图**(三主题 + 依赖一览)。
- 每主题(主线 / 认知补齐 / 行动):一句结论 → `<checkbox>` checklist(关键项标 今晚 / 本周 / 下周)→ 主题图 → **相关文档**(`↳` 行挂可点链接)。

## 三 · 路线图
> 全量任务按优先级,短 / 中 / 长期初步路线。
- 一句结论先行 → **路线图**(短 / 中 / 长 三栏 × P0/P1/P2,**任务要全、别漏**)→ 三条 bullet 要点化收口。

- **末尾 callout(📌 pushpin)**:找人(要联系 / 协调的人)+ 一句"材料自取"。

## 本类型专属硬规则
1. **知识总结只记「我不会、别人讲的」**——自己讲过 / 已会的不进。
2. **标题名词短语**,不带自述后缀(对齐 `lark-doc-writer` §1.5)。
3. **材料自取**:列依赖前先到「个人知识库索引(AI)」+ Drive + wiki 搜;**自己能找到的材料挂链接、不列「等 X 给」**;只把真找不到的列为待要(呼应 `feishu-task-management/memory.md` §6.1/§6.3)。
4. **每段都配图**:知识总结 = 聚焦小图(只画新点);待办 = 总览 + 主题图;路线图 = 优先级图。**公式化链路用 ASCII(`<code>`),其余渲染 PNG 嵌 Image(27)**。
5. **作图管线**:本地 SVG → headless Chrome `--force-device-scale-factor=2.5` → PNG → 嵌入;**嵌入前必须自己 `Read` 看一遍渲染结果**(盲画必裁切:内容超画布、ASCII 超 72 显示列右切)。手绘图的原型 / 配色 / 字号闸 / 渲染脚本 = [`dag-flow-diagram/references/hero-svg-design-system.md`](../../dag-flow-diagram/references/hero-svg-design-system.md)(**画之前读它**,四种原型直接抄 `dag-flow-diagram/templates/hero_*.svg`);落地嵌图走 `lark-cli docs +media-insert --selection-with-ellipsis "<caption 原文>"`。
6. **可读性 + 平衡细节**:结论先行、要点化、去 AI 化;讲清机制但不冗长。

## 变体:多人周会 · 精简版(2026-07-29 经用户验收)

用户要「内容不要太多、突出核心 insight + 两个人的待办」时,把三段式换成下面这版(骨架照抄,段名可换):

1. **一 · N 条主线与公共依赖** — 一句话点出**几条线共用哪个上游**(这类会最实的结构性发现往往就在这儿)→ 全景图(三列泳道:上游 / 现状 / 本周要交的)→ 一段说清各线本周交的东西不一样、谁卡谁。
2. **二 · N 条核心 insight** — 每条一个 H3 **判断句**(不是话题名):「X 是 A 的问题,不是 B 的问题」「X 被当成了 Y,而它只是 Z」这种句式。每条 2–3 段:结论 → 机制 / 归因 → 未闭环的部分;需要图的挑归因图 / 机制对照图,横向对比上原生表格。**只写会上真被推翻或纠正的认知,进度陈述不进这节。**
3. **三 · 两个人的待办** — 一段讲清依赖(谁是串行链、谁可并行、外部约束是什么)→ owner 泳道时间线图 → 按人分节的 `<checkbox>`,每条挂 `—— 今晚 / 本周`。
4. **末尾 📌 callout** — 要找的人(逐个标"找他确认什么")+ **本周必须定下来的口径**(把开放问题收在这里,比散在正文更容易被追)。

与原三段式的取舍:**不写"路线图"**(周会级别排期会过时)、**不写"我补到的认知"式自述**(多人会议要中性叙述);知识总结压成 insight 判断句。

## 编排(内容复杂、多模块时)
先吃透会议 → 列框架定要点 → 落一份共享 spec → **并行子智能体**(找 context + 作图设计)→ 主智能体渲染图 + 组装 → **并行子智能体对抗式审查**(视觉 + 事实 + 写作规范)→ 迭代。详见 `lark-doc-writer` §7.5。
