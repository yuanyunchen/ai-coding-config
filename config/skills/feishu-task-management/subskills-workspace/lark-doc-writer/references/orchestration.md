## §7.5 复杂 / 多文档写作编排(一整套学习体系 / 多篇 + 多图)

写**多篇成体系**(如一套学习文档 main + B1..Bn)或**单篇含多张图**、量大到值得拆并行时,按下面流程编排——**作图走并行、审查走双线**:

1. **rebrief(共享一份 md 规格,每篇 / 每图一节)**:动手前先写一份规格 md,把全局风格(命名 / 图骨架 / 配色 / 口径)放总则,每篇 / 每图各一节列各自的边界、图位、数据来源级别(§0.3 数字来源分级)。这份 md 是所有子智能体的**单一权威**,复用内容只写一次。
2. **并行 per-doc / per-图 子智能体(技能给文件路径,呼应全局 Rule 6「子智能体派发」)**:每篇文档 / 每张图派一个子智能体并行跑。子智能体无记忆、不自动继承规则——dispatch 时**以文件路径给上下文**(传规格 md 路径 + 本 skill / doc-trio / 作图 skill 路径),不在 prompt 里重述规则;点名该 invoke 哪些 skill。
3. **视觉 + 内容双线审查(两条都要走,缺一不可)**:**视觉线** = Chrome 实渲(走 claude-in-chrome,见全局 Rule 5,**不用 computer-use**)核清晰 / 不糊 / 不堆砌 / 跨篇统一;**内容线** = 对照事实源核图的事实 / 逻辑 / 非重复 / 口径,并做**跨篇数字对账**(§10)。
4. **落地飞书**:嵌图走 [`references/media-embed.md`](references/media-embed.md) 管线;多篇并行时每篇独立"加协作者 → … → 删协作者",互不干扰。
5. **核验**:逐篇回读过 §10 自检清单 + 跨篇一致性(口径 / 级别 / label / 占位清零)。

> 分工边界:本节管**多文档编排的流程**;学习文档单篇的章节骨架与图位标准在 `doc-trio` learning_doc(本节不重述骨架)。
