# 视角模板库 / Perspective Templates

按文档类型(判型见 [`doc-types.md`](doc-types.md))列出该类型该覆盖的角度。**写作时**当 checklist 用:逐条问"我这篇有没有讲清楚这个角度",有缺就补。**改写时**当审查清单用:对照查文档是否漏了关键板块。

每条模板格式:**视角名称** | 这个角度要讲清 / 要覆盖什么

---

## 技术类

### 系统架构设计文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| A-T1 | 关键流程是否有图文说明 | 判断核心流程是否有流程图或时序图，有则提取图所在段落及配套文字。 |
| A-T2 | 模块划分与职责边界是否清晰 | 判断各模块的功能边界和协作关系是否有说明，有则提取模块列表与职责描述。 |
| A-T3 | 方案选型与决策依据是否说明 | 判断是否有多方案对比及最终选型理由，有则提取对比维度和结论。 |
| A-T4 | 扩展性与容量瓶颈是否有前瞻分析 | 判断方案是否评估了未来规模增长下的瓶颈，有则提取容量/扩展性分析段落。 |
| A-T5 | 与现有系统的兼容性是否说明 | 判断是否有对已有系统影响的分析，有则提取兼容性或改造成本说明。 |

### 单点技术实现文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| B-T1 | 实现步骤是否有清晰的执行顺序 | 判断实现过程是否按先后顺序说明，有则提取步骤列表。 |
| B-T2 | 核心数据结构或状态变化是否说明 | 判断关键数据模型、状态机或中间态是否有定义，有则提取相关描述。 |
| B-T3 | 边界条件与异常场景是否列出 | 判断是否有对边界、降级、异常路径的说明，有则提取相关条目。 |
| B-T4 | 实现方案的前提假设与适用范围是否明确 | 判断文档是否说明了"在什么条件下成立"，有则提取假设与约束。 |

### 接口/API 规范文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| C-T1 | 接口定义是否集中清晰 | 判断接口出入参、返回码是否有统一章节，有则提取接口列表与关键字段。 |
| C-T2 | 调用示例是否完整 | 判断是否有可直接使用的请求/响应示例，有则提取示例代码段落。 |
| C-T3 | 错误码与异常处理是否有说明 | 判断是否有错误码枚举和处理建议，有则提取错误码列表。 |

### 技术方案评审文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| D-T1 | 对比维度是否明确且一致 | 判断多方案对比是否使用了统一维度，有则提取对比表或对比段落。 |
| D-T2 | 最终选型结论与理由是否明确 | 判断是否有清晰的"选A不选B"的决策理由，有则提取决策说明。 |
| D-T3 | 风险与外部依赖是否识别 | 判断是否列出方案落地的风险点和依赖项，有则提取风险清单。 |

## 产品类

### PRD

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| P1 | 业务价值与目标是否明确 | 判断文档是否清晰说明"做这件事解决什么问题、带来什么价值"，有则提取目标和价值陈述。 |
| P2 | 用户场景是否有具体故事线 | 判断是否有用户视角的使用路径或典型场景描述，有则提取场景段落。 |
| P3 | 关键指标是否定义 | 判断是否有可衡量的成功指标或验收标准，有则提取指标定义。 |
| P4 | 核心交互逻辑是否有分支说明 | 判断是否覆盖了主流程之外的异常/分支路径，有则提取分支流程描述。 |

### 立项文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| I1 | 投入产出是否有估算与依据 | 判断是否有资源投入与预期收益的对比说明，有则提取ROI相关段落。 |
| I2 | 不做的代价是否说明 | 判断文档是否分析了不立项的机会成本或风险，有则提取相关陈述。 |
| I3 | 方案可行性是否有论证 | 判断是否有技术/资源/时间维度的可行性分析，有则提取可行性结论。 |

## 分析类

### 调研文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| R1 | 对比维度是否明确且一致 | 判断多方案/竞品对比是否使用了统一维度，有则提取对比表或段落。 |
| R2 | 是否提出了 N 个可行方案 | 判断是否有可操作的备选结论（而非仅现象描述），有则提取方案列表。 |
| R3 | 差异点与优劣是否清晰标注 | 判断对比结论是否有明确优劣或推荐判断，有则提取结论性段落。 |

### 数据分析报告

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| D1 | 结论是否有数据支撑且可溯源 | 判断每个关键结论是否有对应数据引用或来源说明，有则提取结论+数据对。 |
| D2 | 异常波动是否有解释与归因 | 判断报告是否对数据异常点进行了说明，有则提取异常描述和归因段落。 |
| D3 | 核心漏斗断点是否定位 | 判断分析是否指出转化/留存链路上的关键流失节点，有则提取漏斗分析段落。 |

### 商业分析/BD文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| B1 | 市场规模与目标份额是否有估算依据 | 判断是否有TAM/SAM/SOM或类似市场空间估算，有则提取数据与来源。 |
| B2 | 核心壁垒与差异化优势是否说清楚 | 判断是否明确了"为什么是我们而不是竞争者"，有则提取差异化优势描述。 |

## 总结类

### 述职文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| V1 | 目标-过程-结果是否结构化 | 判断三段是否齐备且逻辑连贯，有则提取对应段落各一份。 |
| V2 | 是否有量化指标和关键案例 | 判断是否用数字和具体事例支撑结论，有则提取数据点和案例描述。 |

### 复盘文档

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| F1 | 根因是否定位到具体归因层 | 判断复盘是否跳出"现象描述"，有明确的根因层归因（人/流程/工具），有则提取根因列表。 |

|---|---|---|

## 通用兜底视角（U1–U5）

适用于文档类型不明确、混合型文档或用户未指定视角时。

| 编号 | 视角名称 | 判断 / 提取 |
|---|---|---|
| U1 | 核心结论或建议是否有明确表述 | 判断文档是否有清晰的最终结论或行动建议，有则提取结论性段落。 |
| U2 | 背景与问题定义是否说清楚 | 判断文档是否交代了"为什么写这篇文档"，有则提取背景与问题陈述。 |
| U3 | 关键术语或概念是否有定义 | 判断文档是否解释了专有名词或核心概念，有则提取定义列表。 |
| U4 | 有没有下一步行动或待确认事项 | 判断文档末尾是否有Next Step或TODO，有则提取待办事项。 |
| U5 | 有没有关键附件、图表或外部参考 | 判断文档是否引用了外部链接、图表或附件，有则提取引用资源列表。 |
