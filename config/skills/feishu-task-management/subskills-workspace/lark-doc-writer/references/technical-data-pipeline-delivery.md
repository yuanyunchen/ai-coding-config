## 信息架构

### 开头概述

只放一个蓝色概述 callout，不另建“项目范围与交付口径”章节，也不默认增加橙色 Context：

- 第一段用自然语言说清“做什么、最终交付给谁、如何使用”。
- 其后最多 4–5 条主干：覆盖范围、日期合同、核心口径与排序、事件或更新合同、必要边界。
- “相关文档”放在概述末尾，使用纵向列表；每项为可点击标题加一句用途介绍。
- 不并排放链接，不写“本地交付文件”，不上传 SQL 附件。
- 代码仓若只负责某个字段处理过程，链接放到对应字段处理文档；主文档只链接该文档，不直接再链代码仓。
- 只有确有溯源审计需求且用户要求展示原始材料时才增加 Context。技术交付默认不加。

### 推荐章节

1. 数据链路：一张简化主图加一段自然解释。
2. 表结构与更新合同：表对象、数据形态、正式任务和更新方式。
3. 计算收敛与日更机制：拆为“中间层计算收益”和“日更调度与事件生成”。
4. 下游读取合同：用途、可调参数、排序和输出字段。
5. 生产验收：真实运行量、时延、质量门禁和结论。
6. 附录：排查、验数、临时分析 SQL。

章节名用业务名词短语，不写“两个中间表为什么有价值”这类问句，也不为了形式单列“范围”“入口”“文件”章节。

## 内容密度

- 图负责层级、关系、时序和机制；文字负责说明为什么、数据口径和边界。
- 图后补一段自然说明，通常 3–5 句；不能只有图，也不能把图中文字逐句复述。
- 参数、事件判定、对象合同、验收结果用短表，不写成长段。表前只需一句说明。
- 一段只讲一个判断；连续正文超过约 6 行时，优先拆成表、图或短列表。
- 每个图、表、段落都应提供新信息。主图已经表达的细节，不在正文和分图中重复三遍。
- 真实名称、真实数量和真实边界优先；无法证明的运行收益标为代理估算或不写。
- 表格正文少用粗体；只突出需要扫描定位的事件类型或结论，不把整列对象名全部加粗。

## 表对象合同

对象总表推荐列顺序：

1. 表对象：写正式业务对象名，不写 A/B/C 或“原始表1”。
2. 表类型：使用“数据源”“中间表（新增）”“最终表（新增）”。
3. Hive 表：表名本身链接 DataLeap，不另建“表入口”章节。
4. 粒度 / 核心形态：明确主键粒度、数组或 JSON、日内是否去重等。
5. 正式任务与更新合同：任务正式名称直接链接 Dorado；写覆盖、追加、TTL、依赖和串并行语义。

必须显式说明源表到中间表的形态变化和被固化的计算，读者应能据此判断中间表是否有价值。

## 链接与引用

- 平台对象的链接贴在对象名上：Hive 表名链 DataLeap，任务名链 Dorado。
- 相关文档集中在概述末尾；纵向排列，每项加一句作用。
- 不增加重复的“相关链接”“表入口”“任务入口”“本地文件”章节。
- 主文档只保留读者需要的入口。实现仓、脚本目录等细节下沉到对应专项文档。
- 链接必须在 transcript 中可回读；渲染后再确认可点击。

## SQL 展示

- 每段 SQL 使用单层折叠代码块：`<pre caption="{用途} SQL" lang="SQL"><code>…</code></pre>`。
- caption 必须以“SQL”结尾；不要再加一个 H3 包住同名折叠块。
- 禁止“先展开标题，再展开一层代码”的双重折叠。
- 不用附件承载 SQL；核心取数 SQL 放正文，辅助 SQL 放附录。
- 禁止 `SELECT *`。只输出下游合同字段；商品标识、稳定排序 rank、来源字段若对消费有用就保留，过程消耗、窗口参数和中间审计信号不随意暴露。
- `LIMIT` 由业务合同决定。默认无限时直接省略 `LIMIT`；有首日固定总量或读取配额时显式写出，并在表格中说明。
- 字段列表可以合理并排换行，不强制每字段单独一行；以飞书代码块宽度内可读为准。

## 三层验收

### Transcript

- 概述包含必要口径和纵向相关文档，没有独立“项目范围与交付口径”“本地交付文件”。
- 表名和任务名直接带链接；没有 A/B/C 代号。
- 每个 SQL 只有一个折叠层，caption 含“SQL”，没有 SQL 附件。
- 章节、图号、表头、输出字段、日期和参数与当前合同一致。

### 图片

- 用图片查看工具看最终 PNG，不以 SVG 源码或文件尺寸代替视觉检查。
- 5 秒内能说出层级、主流向和最终输出；节点与计算过程一眼可区分。
- 在约 700px 宽度仍能读清标题、节点名和关键字段；无裁切、重叠、细小脚注或交叉线。
- 主图保持简洁；细节由计算收益图和日更图承担。

### 飞书渲染

- 用浏览器检查蓝色概述、表格列宽、图片缩放、链接、折叠 SQL 和章节层级。
- transcript 证明内容与结构，浏览器证明视觉与交互；两者都通过才交付。
- 最终回读记录 revision、图片数、表/任务链接数和 SQL 折叠块数。
