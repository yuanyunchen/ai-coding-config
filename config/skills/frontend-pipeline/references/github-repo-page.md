# GitHub 仓库主页(README)与 GitHub Pages 发布

> 2026-11-04 建(posthog-impact-dashboard 交付复盘:截图太小、核心图太散、竖向流程树、截图里残留旧数字)。
> 适用:仓库主页要给外部读者看(评审、招聘方、协作者)。总纲五条照常适用,本文件只写 README 特有的部分。

## 一、结构(自上而下)

1. **标题 + 一句话定位**:这是什么、回答什么问题。
2. **在线链接**:每个可访问页面一行(表格或徽章),第一屏就能点到。
3. **核心方法**:≤3 点,每点一两句。
4. **大图**:见第二节。
5. **运行 / 复现**:最少的命令。
6. **仓库结构**:目录 → 一句话,放在末尾。

耗时、局限等其他信息一行一条。不写过程叙事。

## 二、图片

- **≤6 张,每张有明确角色**。参考组合:产品首屏、产品详情、关系图总览、关系图局部、架构主链、架构分层。按项目替换,不凑数。
- **全部整宽单列**(`<img src="docs/assets/x.png" width="100%">`):GitHub 正文宽约 880px,并排两张就看不清;不拼贴小图。
- **架构图横向**:主链一张(从左到右),分层或细节一张;不用竖向 Mermaid 树(GitHub 里渲染得又长又窄,也和深色截图不搭)。
- **截图 2x 并只截目标元素**:Playwright `device_scale_factor=2`,按 selector 截,不带浏览器空白;主题与产品一致(产品是深色就截深色)。
- **内容一改就重截**:图放 `docs/assets/`,文件名表意;截图里的旧数字是最隐蔽的不一致。
- 每张图上方一行小标题说看什么,不在图下复述图里的文字。

## 三、视觉

- 「fancy」靠大图和留白,不靠堆徽章、emoji、分隔线;徽章只放真有用的(在线链接、许可证)。
- 标题层级 ≤3;段落 ≤3 行。

## 四、静态站发布到 GitHub Pages

- **默认走 `gh-pages` 分支**:`git subtree split --prefix <站点目录> -b gh-pages-build` → `git push origin gh-pages-build:gh-pages` → Pages 源设为 `gh-pages` / 根目录。这条路不需要 token 的 `workflow` 权限;token 缺这个权限时,推 `.github/workflows/*` 会被拒。
- 有 `workflow` 权限时也可用 Actions 部署;两种方式二选一,不并存。
- 站内链接用相对路径,部署在 `/<repo>/` 子路径下才不会断。
- **发布后核验**:每个 URL 返回 200;`curl` 抓页面,grep 一个刚改过的数字,确认是新版本;浏览器 0 console error;加载 < 3 秒。
