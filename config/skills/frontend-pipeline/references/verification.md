# 验证标准与循环

验证统一用内部 `webapp-testing`(Playwright)。两个带验证的档位用**不同清单**:简单+验证 → 「普通验证」;复杂+验证 → 「高质量验证」。

## 验证循环(每轮:测试 → 反思 → 规划 → 执行)

循环到无主要问题再交付。**每一轮都按这个节奏走,不要"看到问题就随手改"**:

1. **测试**:渲染/打开产物(pdf/slides 用 `page.pdf()` + 逐页/整页截图),对照该档位清单逐项过,把发现的问题记进 `frontend_qa.md`。
2. **反思**:这些问题哪些是表面症状、哪些是根因?局部修补能解决,还是布局/结构/设计系统整体有问题?
3. **规划**:基于反思,在 `frontend_qa.md` 列出本轮要改什么、按什么顺序(先结构后细节)。
4. **执行**:按规划改。
5. 回到第 1 步重测。全部通过 → 提交。

### 最大轮数

| 档位 | 上限 | 目标 |
|---|---|---|
| 普通验证(简单+验证) | **3 轮** | 改到「无主要问题」(布局不崩、能用、内容齐全)即可交付,不追求极致 |
| 高质量验证(复杂+验证) | **5 轮** | 做极致优化——每轮不只修 bug,还主动找可提升处。若反思判断布局/信息架构/设计系统整体有问题或质量明显有提升空间,**必要时做大规模重构**(重排版面、重构组件、重做 token),不在烂结构上打补丁 |

达到上限仍有未解决的**主要问题** → 停下,在 `frontend_qa.md` 写明剩余问题与原因,向用户报告。不硬交付,也不超上限继续刷。(艺术分支按普通验证,上限 3 轮。)

## 总纲五查(所有验证档,给人看的产物)

按 `~/.claude/skills/design-principles/SKILL.md`「总纲」表逐条打勾,看渲染截图查,不看源码:
直观(5 秒说得出重点)· 文字比例(每节先图/表/卡片,正文 ≤3 要点或 ≤6 行)· 不重复(同一事实只出现一次,全员相同的元素已删)·
不用机器腔(连读三条句式不雷同)· 重点突出不散乱(每屏一个焦点,每个视觉元素答得出「删掉它读者少知道什么」)。

## 普通验证(简单+验证档)

目的:低成本兜底,保证「能用、不崩」。通常一两轮清完。

- [ ] 总纲五查(上节)
- [ ] 布局不崩:无横向溢出、无重叠/截断
- [ ] 文字可读:对比度够、字号合理
- [ ] 无 console error
- [ ] 移动端可用:关键断点不崩
- [ ] 关键交互可响应:按钮/链接/表单/翻页
- [ ] 内容齐全:用户要求的要素都在
- [ ] 本地双击(`file://`)和部署后的 URL 都打开过
- [ ] 内容改动后,README / 文档里嵌的截图已重截(旧截图里的旧数字最难发现)
- [ ] 多页交付:跨页面、README、架构图里的数字逐个对回数据源

## 高质量验证(复杂+验证档)

目的:达到可交付/对外的专业水准。循环到全部通过。含普通验证全部项,另加:

- [ ] 设计系统一致:颜色/字体/间距/圆角/阴影遵循 token,无随手硬编码值
- [ ] 对比度达 WCAG AA:正文 4.5:1、大字 3:1
- [ ] 信息层级清晰:视觉权重与内容重要性匹配
- [ ] 间距节奏统一:遵循 spacing scale
- [ ] 状态完整(按适用):hover/focus/active、空态、加载、错误
- [ ] 可访问性:语义标签、focus ring、aria、`prefers-reduced-motion`
- [ ] 响应式在主要断点均成立:桌面/平板/移动
- [ ] 性能合理:无明显卡顿、资源不过大

**内容面向读者**(产物要给团队外的人看时必查,细则见
`~/.claude/skills/design-principles/references/writing.md`):

- [ ] 念给一个非目标读者听,首屏没有会被打断提问的地方
- [ ] 反向也成立:删到这个程度,真要用它的人还拿得到他要的
- [ ] 首屏禁用清单逐类查过(代码片段 · 内部参数串 · 编号当主语 · 未解释的缩写 · 黑话 · 工程过程自指)
- [ ] 折叠掉的内容**完整可达**,首屏里指向它的引用仍然成立
- [ ] 对象的定位**不依赖它在流程里的位置**,也不解释我们的建模决定

## 各类型专属验证项

- **web**:首屏观感、SEO 基本项(title/meta/语义结构)
- **pdf**:`@page` 尺寸正确、分页无错位、印刷边距/出血、导出 PDF 与预览一致
- **interactive**:核心交互流程跑通、状态切换正确、无运行时报错;每个会算出结果的控件在极值处单独测过(见 `match-reference.md` 二)
- **slides**:逐页无溢出、母版一致、16:9 比例、翻页可用、导出 PDF 正确

## 艺术产物验证(`canvas-design` / `algorithmic-art` 分支)

艺术分支**不套「高质量验证」的设计系统清单**(token/WCAG/spacing scale 对艺术作品不适用),改用轻量的、以"成品观感正确"为目标的检查,按上面的验证循环走(上限 3 轮):

- **canvas-design(静态 PNG/PDF)**:
  - [ ] 无任何元素溢出画布、无重叠;全部元素在边距内、留白充分
  - [ ] 字体从 `canvas-fonts/` 正确加载、无 fallback 乱码
  - [ ] 配色克制一致(有限色板)
  - [ ] 导出文件清晰无锯齿、尺寸正确
- **algorithmic-art(交互 HTML)**:
  - [ ] 无 console error;canvas 正常渲染
  - [ ] 参数滑块实时生效;seed 可复现(同 seed → 同输出)
  - [ ] seed 导航(prev/next/random/jump)+ regenerate/reset/download 全部可用
  - [ ] 动画(若有)流畅不卡顿
