# Starmap 交互契约

这份契约是几十轮"太灵敏 / 看不到惯性 / 停不下来"的反馈调出来的。
常量的可执行版本在 `assets/starmap.js` 顶部；本文解释每个数字的来历，
以及**症状 → 该动哪个数**的对照。

## 常量总表

| 常量 | 值 | 管什么 | 越大 / 越小 |
|---|---|---|---|
| `panGain` | `1.25` | 拖拽平移增益 | 1.0 跟手但钝；1.5 起开始飘 |
| `zoomGain` | `.0042` | 滚轮缩放灵敏度 | 更大更急躁；更小要滚很久 |
| `kMin / kMax` | `.22 / 3.4` | 缩放范围 | — |
| `minLegible` | `.55` | 自动取景的可读下限 | 低于此宁可溢出也不再缩 |
| `clickDelay` | `240ms` | 单击延时 | 更短双击会漏判；更长单击发木 |
| `hopWeight` | `[1,.46,.18,.062]` | 跟随幅度（按跳数） | 尾项调大 = 波及更远 |
| `hopStiff` | `[1,.028,.019,.013]` | 跟随刚度（按跳数） | 调小 = 更滞后、惯性更明显 |
| `followSpan` | `340` | 空间半衰距离 | 调小 = 远处节点更不受影响 |
| `damping` | `.68` | 弹簧阻尼 | 调大惯性更长；>.8 会甩过头来回晃 |
| `bow` | `.085` | 连线弓度 | 见 `visual-system.md` |
| `xgap / ygap` | `202 / 200` | 分层列距 / 行距 | 见 `layout.md` |

## 相机

**平移增益 1.25。** 1:1 跟手在星图这种"大画布小视口"的场景里显得钝 ——
手要划很多次才能走完全图。1.25 是"比手快一点但仍然可控"的点，
1.5 以上开始出现"图从手里滑走"的感觉。

**缩放是连续的，不是档位的。** `k *= exp(-clamp(deltaY,±140) * .0042)`。
离散档位（每次 ×1.2）在触控板上会一格一格跳，很难对准。
指数形式让"轻轻滑一点"和"猛滑"都有对应的响应。`±140` 的 clamp 是防止
某些鼠标一次 deltaY 上千直接把图缩没。

缩放锚点：滚轮以**光标**为锚点，右下按钮以**可见区中心**为锚点。
可见区 = 视口减去抽屉宽度 —— 抽屉开着时若仍以视口中心为锚，
焦点会跑到抽屉底下去。

**自动取景带可读下限。** `fitView` 先算塞得下的 `k`，但如果那个 `k` 低于
`minLegible=.55`，节点标签就已经糊了，再缩没有意义。此时保底到 `.55`，
容许水平溢出，并把镜头**贴到左端** —— 让人从数据流的起点开始读，往右平移。
`.96` 的安全边防止贴边裁掉标签。

## 单击与双击

浏览器的 `click` 会在 `dblclick` 之前先触发。不处理的话，双击放大会先闪一下抽屉。

```js
click:    clearTimeout(t); t = setTimeout(执行单击, 240)
dblclick: clearTimeout(t); 执行双击
```

240ms 是系统双击阈值的典型值。更短会漏判双击，更长单击会有明显延迟感。

**拖拽不算点击**：`mousedown` 时 `moved=0`，每次 `mousemove` 递增，
`click` 里 `moved>3` 直接返回。阈值 3 而不是 0，是因为按下时手会抖。

行为约定：

| 操作 | 结果 |
|---|---|
| 单击节点 | 打开抽屉 + 缓动把该节点移到可见区中心 |
| 单击连线 | 打开抽屉展示这条关系 |
| 单击空白 | 关闭抽屉 |
| 双击节点 | 放大到 `clamp(k*1.9, 1.4, 2.2)` 并打开抽屉 |
| 双击同一节点 | **收回全景**（连抽屉一起关） |
| 双击空白 | 恢复全景 |

"双击同一节点收回"这条很关键 —— 放大之后如果没有一个明显的返回动作，
人会一直缩小-放大地找路。让触发放大的同一个手势也能撤销它，是最省心的设计。

## 拖拽惯性

这是最难调的一块，中间走过两条弯路：

1. **刚性瞬移**（邻居 = 拖拽位移 × 系数）：机械、没有生命感，而且只在
   `mousemove` 里更新，鼠标停住邻居就立刻停住。
2. **松手后交还全局力导向**：整张图会开始重新收敛，节点漂到别处去，
   人辛苦摆好的位置全没了。

最终方案是**弹簧模型，且拖拽中与松手后是同一套逻辑**：

```
目标位置 = 锚点 + 拖拽总位移 × 权重
每帧：  v = (v + (目标 - 当前) * k) * damping
        pos += v
```

- **权重 `hopWeight`** 决定跟多远：直接邻居跟 100%，一跳外 46%，两跳 18%，三跳 6%。
  超过三跳不跟 —— 再远人就看不出关联，只觉得整张图在抖。
- **刚度 `hopStiff`** 决定跟多快：直接邻居 `k=1`（几乎实时），一跳外 `.028`
  （明显滞后）。**幅度和刚度必须分开衰减**，只衰减幅度会得到"整体一起动"，
  只衰减刚度会得到"远处最后走到一样远"。两者一起衰减才有从中心向外扩散的波感。
- **空间半衰 `1/(1+(d/340)²)`**：跳数相同但物理距离很远的节点不该跟着动。
- **阻尼 `.68`**：滞后量 ≈ `v(1-d)/(k·d)`。阻尼太高（>.8）会甩过头来回晃，
  太低（<.5）就没有惯性可言。

**松手只是让目标停止移动**，弹簧继续把节点收到位、自然停下。
收敛判据是所有节点速度和 < `.05`，然后清零、释放 follow，**不唤醒任何全局物理**。

如果你的图用力导向而不是分层布局，这套仍然适用，但要注意：拖拽期间必须
`return` 掉全局物理步进，否则两套速度积分会打架。

## 键盘与退出

- `F` — 恢复全景（焦点在搜索框时不响应）
- `ESC` — **逐级退出**：弹窗 → 抽屉 → 放大态 → 什么都不做

逐级退出很重要。单一的"ESC 全部重置"会让人在看完一个面板后连视角一起丢掉。

## 控件布局

四角分置，中间永远留给图：

```
左上 搜索                              右上 读数条
                    ［ 星  图 ］
左下 小地图 + 提示行                    右下 缩放 / 全屏
```

- **搜索**默认收窄（200px），聚焦时展开到 262px。它需要存在，但不该抢注意力。
- **小地图**点击回中、拖拽连续回中、双击恢复全景。它同时是"我在哪"的指示器
  （白框 = 当前视野）和导航器。
- **缩放控件**用 16px 描边 SVG 图标，不用 `+`/`−` 文字字符 —— 文字字符在不同
  字体下大小不一。全屏用四角括号符号（`⌐ ¬ ∟ ⌐` 的路径形态），这是 starmap 的惯例。
- **提示行**列出全部手势。它看起来啰嗦，但没有它人不会发现双击和 F。

顶栏读数条只放**全局不变量**（节点数、边数、观测日期）。
放随选中变化的东西会让人以为那是当前对象的属性。

## 开场动效

只做一次很轻的入场：`opacity 0→1` + `translateY(6px→0)`，1s ease-out。
**入场结束后节点就固定在算好的位置**，除非用户拖拽。

不要做"力场收敛"式的开场。它看起来很酷，但代价是：每次刷新布局都不一样，
人无法建立空间记忆，而空间记忆恰恰是图相对于表格的唯一优势。

## 症状对照表

| 用户说 | 动这个 |
|---|---|
| 拖动地图太灵敏 / 太钝 | `panGain` |
| 放大缩小不够灵敏 | `zoomGain`（不要改成离散档位） |
| 看不到拖拽惯性 | `hopStiff` 尾项调小、`damping` 调大 |
| 拖一个动一片，太乱 | `hopWeight` 尾项调小、`followSpan` 调小 |
| 松手后还在飘 | 检查是否唤醒了全局物理；`damping` 调低 |
| 停止拖拽后有滞后位移 | 那是设计；若真要立刻停，`hopStiff` 全调到 1 |
| 双击时会闪一下面板 | `clickDelay` 没生效 / `clearTimeout` 漏了 |
| 缩小后看不清 | `minLegible` 调高，接受水平溢出 |
| 连线动效太抢眼 | 粒子数 2→1、周期 4.3→6、alpha `.47` 调低 |
| 整体太长 / 太挤 | 见 `layout.md`，不是交互问题 |
