## 底层原则

**深空不是为了好看，是为了让发光有意义。** 在浅色背景上，加色合成
（`globalCompositeOperation='lighter'`）会把一切推向白色，光晕变成脏斑。
深底才让"亮度 = 重要性"成为一条可用的编码通道。这条通道一旦成立，
就可以用它做焦点：邻域 `alpha=.72`、非邻域 `.09`，不需要任何额外的边框或颜色变化。

**克制发光。** 星图容易做成霓虹灯。判据是：**关掉所有发光后，信息是否完整？**
如果关掉就看不懂了，说明你在用发光承载信息，那它就不该是装饰性的强度；
如果关掉仍完整，发光才可以放心地弱（本系统的光晕峰值 alpha 只有 `.34`）。

**一个强调色。** 冰蓝 `--ice` 是全局唯一的"可点 / 当前 / 主线"信号。
第二个颜色一旦也表示"重要"，两个都不再重要了。其他颜色都必须绑定到
**具体语义**（琥珀=注意、玫红=异常、青绿=健康、紫=第二类实体），
不能因为"这里想要点变化"就用。

焦点略高于几何中心（`H*.44`）。这一点点不对称让画面有"上方是天顶"的方向感。

## 排版

三套字体各有明确分工，混用会立刻显得业余：

- **Syne**（`--font-display`）：只用于标题与面板大标题。字形独特，用多了吵。
- **Space Grotesk**（`--font-ui`）：正文、按钮、说明。
- **JetBrains Mono**（`--font-data`）：**所有标识符、数字、枚举值、时间戳**。
  这是最重要的一条 —— 表名、字段名、ID 一旦用比例字体，人就不确定
  `l` 和 `1`、`0` 和 `O` 到底是哪个。等宽是正确性要求，不是风格。

**eyebrow 是签名元素**：等宽 + `letter-spacing:.42em` + 全大写 + 左侧渐隐横线。
它出现在顶栏品牌区上方、每个面板分节标题（`.sm-sec`，字距降到 `.26em`）。
大字距只在**短的全大写拉丁**上成立；中文加字距会散架，所以 eyebrow 一律写英文。

字号阶梯很窄：`8.5 / 9 / 9.5 / 10.5 / 11.5 / 12.6 / 15 / 19 / 22`。
窄阶梯配合三套字体和三档文字色，足够拉开层次；再加字号只会让页面更乱。

中文正文行高 `1.6–1.82`，比拉丁常规的 1.5 高 —— 中文字面率高，行距不够会闷。

## 材质与图层

四层，z-index 是硬约束：

```
z:20  检视抽屉 / 弹窗    ← 半透明 + blur(22px)，星图在背后若隐若现
z:12  四角控制台          ← blur(12px)
z:10  HUD 顶栏            ← blur(14px)，pointer-events:none，只有子元素可点
z: 4  胶片颗粒 grain      ← opacity .05，9s steps(10) 抖动
z: 3  渐晕 vignette       ← 径向，52% 处开始压暗到 rgba(2,4,10,.62)
z: 0  canvas 星图
```

**玻璃拟态的两个必要条件**：半透明背景 **和** `backdrop-filter: blur()`。
只有半透明没有 blur，背后的连线会穿透面板扎眼；只有 blur 没有半透明，
就是一块不透明板子，玻璃感为零。

**颗粒与渐晕不能省。** 纯 CSS/Canvas 的深色界面会有一种"数字感的平"，
这两层各自很弱（`.05` 和边缘 `.62`）但合起来把画面拉进摄影质感。
grain 用 `steps(10)` 而不是平滑动画 —— 平滑抖动看起来像画面在呼吸，
阶跃才像胶片。周期 9s 足够长，不会被察觉为"有东西在动"。

## Canvas 发光渲染

**用预渲染精灵，不要用 `shadowBlur`。** 实时阴影模糊在几十个节点上就掉帧。
做法是把径向渐变画进一张离屏 canvas 并按 `颜色|半径` 缓存：

```js
g.addColorStop(0,   `rgba(r,g,b,.34)`);   // 核心
g.addColorStop(.16, `rgba(r,g,b,.13)`);   // 快速跌落 —— 这一档决定"实心感"
g.addColorStop(.46, `rgba(r,g,b,.035)`);  // 长尾
g.addColorStop(1,   'rgba(0,0,0,0)');
```

`.16` 处的陡降是关键：线性渐变会得到一团棉花，陡降 + 长尾才像光源。
精灵边长取 `r*3.4*2`，再大是浪费像素，再小会看到方形截断。

**两趟绘制，加色只包住发光。**

```
ctx.globalCompositeOperation='lighter'
  → 连线、箭头、流动粒子、节点光晕
ctx.globalCompositeOperation='source-over'
  → 节点本体、所有文字
```

文字绝不能画在加色层里 —— 加色会让文字与背后的光叠成灰白糊，完全不可读。

**呼吸**：每个节点 `alpha` 乘 `.85+.15*sin(t*tw+ph)`，`tw`/`ph` 由 id 派生
（不要用 `Math.random`，刷新会跳）。幅度只有 ±15%：能感觉到"活着"，
但盯着看不出在闪。

**标签底板**是可读性的硬要求。文字压在发光连线上会被糊掉，所以每行标签
先画一块 `rgba(6,9,19,.82)` 的圆角底板再写字。只在邻域内画底板 —— 
非邻域的标签本来就该退到背景里。

## 节点本体解剖

引擎不画节点本体，`drawNode` 由你实现，因为形状必须编码类型。
一个成熟的节点（以数据表为例）从内到外承载了五层信息：

```
       ● 新鲜度点（右上角，青绿/琥珀/玫红）
   ╭───────────╮
   │   1.5亿   │   ← 圆内：最重要的一个数字，等宽
   ╰───────────╯
    ═══──────      ← 圆外 6.5px 的构成环：分段弧长 = 占比
      商品库        ← 主标签，UI 字体，12.5px
  travel_catalog…   ← 原始标识符，等宽冰蓝，11px  ★
   p_date · 30天     ← 元信息，等宽 8.5px，faint
```

★ **原始标识符必须直接显示在图上。** 只显示中文别名，人就得点开才知道
这是哪张表；而人查数据时脑子里装的是真名。这条被反复验证过。
它也因此成为布局的硬约束——最长的那个真名决定了列距的下限（见 `layout.md`）。

不同类型用**形状**区分，不要只用颜色：表 = 圆，任务 = 旋转 45° 的圆角方块。
颜色可以被遮罩、被 alpha 压暗、被色觉差异影响，形状不会。

大小编码一个连续量（如行数）时走对数：`r = 26 + (log10(v)-lo)/(hi-lo) * 22`。
线性映射会让最大的节点吃掉整个画面。

## 连线

二次贝塞尔，弓度 `sg = (s<t ? 1 : -1) * 0.085`。符号由端点 id 比较决定，
所以 A→B 和 B→A 自动分向两侧、不会重叠。

**弓度是长度与可辨的权衡**：0.14 时曲线优雅但视觉长度被拉长、整张图显得松散；
0.085 更短更直、图更紧凑，同时仍足以分开双向边。低于 0.05 双向边会开始糊在一起。

连线起止点从节点边缘算起（`a.r+4` / `b.r+9`），终点多留 5px 给箭头。

**流动粒子只在邻域内跑**，周期 4.3s、每边 2 颗、两端用 `sin(tπ)` 淡入淡出。
没有淡入淡出，粒子会在端点凭空出现和消失，很脏。
粒子承载的是**方向**，不是活跃度 —— 不要用它的速度或密度去编码数据，
人读不出来，只会觉得晃。

虚线绑定语义：实线 = 确证，`[5,5]` = 存疑/不可读，`[2,6]` = 非因果的观测关系。

**默认态连线要轻**（2026-11-04 实测「线条太重」）：节点几十个、边上百条时，默认连线宽
0.6–1.6px（按权重对数映射）、alpha .12–.25；悬停或聚焦时邻域边加亮到 .7 以上并加宽，
非邻域降到 .05–.09。默认就亮的连线会盖住节点，整张图读成一团线。

**用别的渲染库做 starmap 风格**（cytoscape、d3 等，需要预计算布局或语义缩放时）：
搬 token（深空底、单一冰蓝强调、玻璃面板、eyebrow）、形状编码和本节的连线规则；
发光和粒子是装饰，不搬也不丢信息。

## 降级与可访问性

窄屏按"先丢装饰、再丢辅助控件、画布永远保留"降级：
1100px 丢小地图 → 900px 丢底部提示与顶栏读数 → 520px 丢搜索。

颜色永远搭配第二通道：形状（圆/方）、虚实（实线/虚线）、文字标签。
`--faint` 对 `--void` 的对比度约 3.4:1，只够元信息用；正文必须用 `--dim` 以上。

字体只内嵌拉丁子集，中文走系统栈（PingFang SC / 微软雅黑）。
中文 woff2 动辄几 MB，内嵌会让单文件产物大到打不开，而 starmap 的中文
用不到任何特殊字形。
