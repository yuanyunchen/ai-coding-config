# 更新规则 — 全局记忆的写入纪律(设计核心)

> 管全局三库(定位/时间/知识)的写入;工作区文件归 workspace-management spec §8,两者分工互不越界。checkpoint 只管工作区内部,不碰全局(其边界不因本文件改变)。

## 一、无痕边界(2026-07-02 用户裁决)

- **记忆桶(三库内容:定位卡 / 时间条目 / 知识条目)= 直接操作**:不提示、不审批、不在回复里汇报——静默落盘。可审计与可回滚靠:每条 `updated` 日期 + 枢纽 git 历史(memory-weekly-check 每次跑完 commit)。
- **harness 桶(更改/新增 AGENTS.md 规则、skill)= 走 harness-management update 流程**(按其模式×层级定审批,缺省 none),永不无痕。
- **硬判别(防绕门):按内容性质定桶,不按落点文件定桶**——凡属行为约束(该怎么做 / 禁忌 / 流程 / 触发条件)即 harness 桶,哪怕想写成"知识条目"落枢纽也不行;事实 / 状态 / 偏好取值 / 环境信息 = 记忆桶。

## 二、模式与双入口(v3,2026-07-03;与 workspace-management 三模式同机制,防两向架空)

**模式**(记在枢纽 MEMORY.md 头部模式行;缺省 = auto,维持「里程碑无痕自动」既有裁决;工作区侧缺省 none,两侧独立):
- **--none**:不自动写三库,人调命令才更。
- **--auto(缺省)**:里程碑自动——命中下列判据之一,顺手做「全局 update 三小件」;三库与实际出现较大出入时自动跑 modules/update.md 例程。
  - 判据(写死):任务收尾/归档;阶段完成或方向性决策落定;重要模块/交付完成;用户裁决把一件事定型。
  - 三小件:刷本项目定位卡现状行(+status/updated)→ TIMELINE 补任务级一行(结构=time-index.md)→ 恒真知识条目入检索库(有才写)。
  - **不逐会话、不逐工作项**(工作项粒度归工作区 spec §8;逐会话写=已废 record 的覆辙);也不许「攒到一定程度」被解读成从不写——memory-weekly-check 的 drift 检测双向兜底(判据以该定时任务 prompt 为准:0 条 vs 有活动、或条数 ≥ 活动数×3,都列入报告)。
- **--full**:即时更新,决策/事实一定型即写对应库;新 session 接入或换项目自动跑 modules/recall.md 定向。

**双入口**:自动 = auto/full 模式下 agent 直接执行 `modules/update.md`(不 invoke 命令);手动 = 对话指令或 /project-update 分发(单层 command 已撤销 2026-07-03;原 memory-update 命令 skill 更早已归档)。

## 三、冲突仲裁与纠错

- 仲裁序:**requirement 原文 > 工作区实物 > 全局记忆**——全局记忆与工作区不一致时,以工作区为准修全局(全局是指针,不是真相源)。
- 消解留痕:改动条目刷 `updated`;成批修正由 memory-weekly-check 的 git commit 留历史;语义性矛盾(两处目标表述打架)列给用户,不擅裁。
- 红线:不静默删除任何记忆文件(合并/删除只出建议)。

## 四、维护主体一览(谁写什么)

| 主体 | 写什么 | 频率 |
|---|---|---|
| 主 agent(纪律) | 按模式:auto=里程碑三小件;full=即时;none=不写 | 命中判据时(auto)/ 即时(full) |
| 人调(对话指令 / /project-update 分发 → modules/) | 补记 + 冲突消解 / 只读定向检索 | 用户需要时 |
| memory-weekly-check(定时) | 对账修偏 / drift 检测 / TIMELINE 整理月压缩 / git commit | 每周(浅查:冲突/死链/两跳可达为主,不深入) |
| feishu-weekly-curation(定时) | **只写飞书侧**(双索引/AI 索引候选/控制台),不碰枢纽任何文件 | 每周(错开) |
