## 先选对布局

| 图的性质 | 用 | 理由 |
|---|---|---|
| 有向无环、有明确流向（血缘、依赖、管线、状态机） | **分层 DAG** | 流向即位置，位置可记忆 |
| 无向、看聚类（相似度、共现、社交） | 力导向 / UMAP 预计算 | 没有"方向"可分层 |
| 有环、但主体是流 | 分层 + 把回边排除出分层 | 见下文 `dagIgnore` |
| 节点 > 300 | 预计算坐标（离线跑），运行时只渲染 | 浏览器里跑不动 |

**默认选分层。** 力导向对 DAG 的三个致命问题：层级不齐（同级节点高低错落）、
长边乱窜（一条边横穿全图）、**每次刷新都不一样**。最后一条最伤 ——
人对图的记忆是空间记忆，位置一变，前一次看懂的东西全部作废。

## 分层算法

Sugiyama 框架的三步，实现在 `starmap.js` 的 `layoutDAG()`（Python 复刻见
`scripts/check_layout.py`，两者必须保持一致）。

### 1. ALAP 分层

先算 ASAP（尽可能早：`layer = max(前驱)+1`），得到最大层数 `MAX`；
再算 ALAP（尽可能晚：`layer = min(后继)-1`，无后继则 `MAX`），**用 ALAP 作为最终层**。

为什么用 ALAP 而不是 ASAP：ASAP 会把所有源节点堆在第 0 层，然后一堆长边
横跨好几层去够它们的下游。ALAP 把每个节点推到尽量靠近它的下游，长边自然缩短。

递归里要有环保护（`seen` 集合），否则数据里一旦有环就爆栈。

### 2. 层内重心排序

6 轮扫描，正反交替。每轮里每个节点的排序键 = **相邻层中它的邻居的平均序号**：

```js
ref(n) = mean(pos[m] for m in (正向? 前驱 : 后继) if layer[m] != L)
```

交叉数随轮数单调下降，通常 4 轮就收敛，6 轮是留余量。

### 3. 中位对齐

40 轮迭代，每轮两件事：
- 每个节点向"跨层邻居 y 坐标的中位数"移动 `28%` —— 把链路拉直
- 层内按 y 排序后强制最小间距 `ygap`，冲突时两侧对半推开

步长 `0.28` 是收敛速度与稳定性的折中：更大会在最小间距约束之间来回振荡，
更小要跑上百轮。

最后整体平移使几何中心归零，方便相机处理。

### 环怎么办

分层要求 DAG。有两类边必须排除（`dagIgnore`）：

1. **成环的边** —— 比如"任务读注册表、加工后又写回注册表"。保留它会让
   ALAP 递归退化。排除后它仍然会被**画出来**，只是不参与算层。
2. **非因果的边** —— 比如"这两张表实测有 0.61% 重叠"这种观测关系。
   它不表达先后，硬塞进分层会凭空多出一层。

排除的边也不画进小地图 —— 小地图要传达的是骨架。

## 参数整定

只有两个数：`xgap`（列距）和 `ygap`（行距）。它们控制的其实是**长宽比**。

反馈通常是"整体太长了"或"太挤了"。翻译过来：

| 反馈 | 动作 |
|---|---|
| 整体太长 / 像一条带子 | `xgap` ↓ 且 `ygap` ↑ —— **两个一起动**，只收 xgap 会变成一团 |
| 连线太长 | `xgap` ↓（边长几乎线性跟随 xgap） |
| 上下太挤 / 标签叠 | `ygap` ↑ |
| 左右标签叠 | `xgap` ↑ —— 但先看下一节，这可能是死路 |

参考值：7 层 13 节点的图，`xgap=202 / ygap=200` 得到长宽比 2.6、平均边长 211、
1440px 视口自动缩放 `k≈1.03`。长宽比控制在 **2.0–3.0** 之间读起来最舒服；
超过 3.5 就是带子，人需要横向扫视才能看完。

## 用脚本量，不要用眼睛量

`scripts/check_layout.py` 复刻了同一套布局并输出可判定的数：

```bash
python3 check_layout.py data.json \
  --label-fields raw,name --label-px 11 \
  --ignore "taskA>tableX,tableA>tableB"
```

```
节点 13 · 边 14 · 层 7（每层 [2, 2, 3, 3, 1, 1, 1]）
  包围盒        1292 × 497   长宽比 2.60
  边长          均值 211  标准差 28
  交叉 0   回边 0
  标签最小余量  -0px  （registry ↔ t307341729）   ← 已重叠
  1440px 视口下自动缩放 k = 1.03
```

判据：

- **回边 ≠ 0** → `dagIgnore` 漏了成环的边，先修这个，其他数都不用看
- **边长标准差 > 均值 × 0.45** → 有长边乱窜，分层没吃住结构
- **长宽比 > 3.5** → 带子
- **标签余量 ≤ 0** → 已重叠
- **k < 0.55** → 全景下看不清，图太大了或视口太小

扫参找拐点：

```bash
python3 check_layout.py data.json --sweep xgap 170 240 10 --label-fields raw,name
```

## 标签宽度是硬约束

这是最容易被忽略、也最容易走进死胡同的一条。

`xgap` 的下限不是美学决定的，是**最长的那个标签**决定的。当一个 44 字符的
原始表名画在节点下方时，它的半宽就有 145px；如果相邻列有另一个标签，
两者的半宽之和加上最小空隙，就是 `xgap` 的物理下限。

实例：`travel_catalog_embedding_product_registry_di`（44 字符，11px 等宽）
把 `xgap` 的下限钉在 **202px**。低于此标签必然重叠。

所以"整体太长"这个反馈，在 `xgap` 已经到底时**不能靠继续收 `xgap` 解决**。
剩下的选项按代价排序：

1. **放 `ygap`** —— 改善长宽比而不动列距。首选。
2. **把长列折成两行** —— 层数减半，但流向感变弱。
3. **截断原始标识符** —— 不推荐。真名是人认表的锚点（见 `visual-system.md`）。
4. **改小标签字号** —— 到 10px 以下就开始难读了。

`check_layout.py` 的宽度是按 "等宽拉丁 0.6em / CJK 1.0em" 估的，误差 ±5%。
余量卡在 ±15px 以内时，去浏览器里用 `ctx.measureText()` 实测复核。

## 什么时候该用力导向

分层不是万能的。以下情况改用力导向或预计算坐标，并传 `layout:'none'`
自己写 `x/y`：

- 图本质无向、要看的是**聚类**而非流向
- 节点数 > 100 且层数很浅（分层会得到极宽的几列）
- 已有语义嵌入（UMAP / t-SNE 的二维坐标），位置本身就是信息

用力导向时务必**跑到收敛再冻结**，把最终坐标存下来，运行时直接读。
不要让力场在用户面前收敛 —— 理由同"开场动效"那一节。
